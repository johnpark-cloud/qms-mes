# 화면 설계: 연결을 한눈에 보고 관리하는 화면

- 작성일: 2026-11-11
- 상위 문서:
  - `2026-11-11-data-foundation-design.md` (단계 A~J)
  - `2026-11-11-data-model-detail.md` (칸 설계, 12절 관계 지도)
- 기존 화면 규칙:
  - `2026-11-03-notion-style-frontend-design.md`의 P1~P7
  - `DESIGN.md`의 토큰("Related Records", "LOT Timeline" 컴포넌트 포함)
- 상태: 초안이다. **[내 판단]** 표시는 사용자와 합의하지 않고 내가 정한 것이다.

## 1. 목표

사용자 요청:
- 데이터 관리가 쉽다.
- 접근성이 좋다.
- 확장하기 쉽다.
- 데이터를 쉽게 연결한다.
- 연관성을 한눈에 보고 관리한다.

화면이 지켜야 할 것으로 바꾸면 이렇다.

| 요청 | 화면에서 지킬 것 | 확인 방법 |
|---|---|---|
| 관리 쉬움 | 어느 목록에서든 필터, 저장된 보기, 일괄 수정, 엑셀 왕복이 같은 방식으로 된다 | 새 표를 하나 더해도 목록 화면 코드를 따로 쓰지 않는다 |
| 접근성 | 키보드만으로 모든 일을 한다. WCAG 2.2 AA를 지킨다 | e2e 브라우저 검사에 키보드 경로를 넣는다 |
| 확장성 | 표를 추가하면 목록, 상세, 연결 패널이 자동으로 나온다 | 관계 레지스트리(U1)가 `_meta`를 읽는다 |
| 연결 쉬움 | 기록 안에서 바로 다른 기록을 고르거나 새로 만들어 붙인다 | 연결 칩 + "새로 만들어 연결" |
| 한눈에 봄 | 모든 상세 화면 오른쪽에 "연결" 패널과 관계 지도가 있다 | U2·U3 |

## 2. 참고한 제품과 가져올 것

| 제품 | 가져올 방식 | 이 앱에서 쓰는 곳 |
|---|---|---|
| Notion | 속성 블록, 관계(Relation) 칸, 백링크 | 상세 화면 상단 속성, 연결 칩, "이 기록을 가리키는 기록" |
| Airtable | 표마다 저장된 보기(그리드·그룹·칸반), 연결 칸에서 바로 새 행 만들기 | 저장된 보기(U4), 인라인 생성(U5) |
| Linear | Ctrl+K 명령, 키보드 우선, 일괄 선택 후 한 번에 바꾸기, 빠른 반응 | 명령 팔레트 확장, 일괄 수정(U6) |
| Attio | 기록 페이지 오른쪽 "관계" 묶음, 개수 배지 | 연결 패널(U2) |
| SAP Fiori | 개체 페이지(Object Page), 상태 색 규칙, 업무용 밀도 | 기존 `fiori.css` 토큰 그대로 |
| GitHub | 타임라인에 연결 이벤트가 같이 보임 | 기록 이력 탭에 "연결됨·연결 해제" 표시 |

- 이들 제품의 이름, 아이콘, 화면 모양은 베끼지 않는다. 방식만 가져온다.
- 외부 라이브러리, CDN, 폰트는 더하지 않는다. React 19 + antd + 직접 쓴 SVG로 만든다.

## 3. 화면 골격 (기존 P1~P3 위에 더한다)

```
┌ 앱 머리: 메뉴 · Ctrl+K 검색 · 내 할 일 · 사용자 ─────────────────────────┐
│ 왼쪽 메뉴        │ 본문                                │ 오른쪽 패널(접힘 가능) │
│ 기준정보         │ [기록 머리] 번호 · 제목 · 상태 칩   │ 탭: 연결 | 지도 |      │
│ 품질(QMS)        │ [속성 블록] 2열 속성                │     이력 | 메모        │
│ 생산(MES)        │ [연결 칩 줄] 거래처·품번·LOT …      │                        │
│ 구매·영업(ERP)   │ [본문 탭] 상세 | 하위 표 | 첨부     │ 연결(12) ▸ 검사 3      │
│ 문서·심사        │                                     │           ▸ 부적합 1   │
│                  │ [저장 막대] 저장 Ctrl+S · 취소       │           ▸ 출하 2 …   │
└──────────────────┴─────────────────────────────────────┴────────────────────────┘
```

- 메뉴 묶음은 상위 문서 5절 모듈 지도와 같다.
- 오른쪽 패널은 기존 "이력·메모" 탭에 "연결"과 "지도"를 더한 것이다.
- 너비가 1100px보다 좁으면 오른쪽 패널은 본문 아래로 내려간다. **[내 판단]**

## 4. 화면 단위 설계

### U1. 관계 레지스트리 (서버)

새 파일 `core/relations.py`. 화면 단위는 아니지만 아래 U2~U6의 바탕이다.

**하는 일**
- 앱 시작 때 `core`·`qms` 모델의 `_meta`를 읽어 관계 목록을 만든다.
  - 정방향 외래키: 이 기록이 가리키는 것
  - 역방향 외래키: 이 기록을 가리키는 것
  - 다대다
  - 일반 연결: `Attachment`, `Evidence`, `Memo`, `StockMove.ref`
- 표마다 화면 이름(`verbose_name`), 대표 글(`__str__`), 상세 화면 주소(기존 `qms.target_url`)를 함께 둔다.

**API**
| 주소 | 돌려주는 것 |
|---|---|
| `GET /api/relations/<app>.<model>/<id>/` | 종류별 묶음: `[{label, model, count, items: [{id, text, status, url}] (최대 5개)}]` |
| `GET /api/relations/<app>.<model>/<id>/graph/?depth=1\|2` | 지도용 점과 선: `{nodes: [...], edges: [...]}`. 점은 최대 60개 |
| `GET /api/relations/.../?kind=<model>&page=n` | 한 묶음의 나머지 목록 |

**권한**
- 묶음마다 사용자의 `view` 권한을 서버에서 검사한다. 권한이 없는 묶음은 개수까지 숨긴다.
- `personal` 앱 모델은 레지스트리에 넣지 않는다.
- 첨부는 3.7의 접근 규칙을 따른다.

**제외 설정**
- 변경 이력(`Historical*`), 내부 표(`DashboardLayout`, `ImportProfile`)는 뺀다.
- 레지스트리에 `EXCLUDE` 목록 한 줄로 둔다.

**성능**
- 묶음마다 `count()` 1번, 앞 5개 조회 1번을 한다. 묶음이 20개면 쿼리 40번이다.
- shortcut: 묶음 수가 30개를 넘어 느리면 개수만 먼저 보내고 목록은 펼칠 때 받는다.

### U2. 연결 패널 "연결"

오른쪽 패널의 첫 탭이다. Attio의 관계 묶음과 Notion의 백링크를 합친 모양이다.

**모양**
```
연결 12                         [+ 연결]
▾ 검사 3                          모두 보기
   IQC-2611-0012  합격  11-10
   IQC-2611-0008  불합격 11-03   ● 부적합 있음
   …
▸ 부적합 1
▸ 출하 2
▸ 첨부 4
── 이 기록이 가리키는 것 ──
   거래처  대한정밀 (승인, A)
   품번    1VDC001 rev B
```

**규칙**
- 위에는 "이 기록을 가리키는 것"(역방향), 아래에는 "이 기록이 가리키는 것"(정방향)을 둔다.
- 묶음 순서: 열린 일이 있는 묶음(부적합·CAPA·보류) → 나머지는 개수 많은 순서. **[내 판단]**
- 각 행에는 상태 칩을 붙인다. 색은 `DESIGN.md` 상태 색 규칙(정상·주의·위험·중립)을 쓴다. 색만으로 뜻을 전하지 않고 글자도 함께 쓴다.
- 행을 누르면 그 기록으로 간다. Shift+누르기는 오른쪽 미리보기 창(P2)으로 연다.
- "+ 연결"을 누르면 이 표와 연결할 수 있는 칸 목록이 나온다. 고르면 U5 선택 창이 열린다.
- 연결이 0건인 묶음은 숨긴다. 맨 아래에 "연결 없는 종류 7개 보기"를 접어 둔다.

### U3. 관계 지도 "지도"

오른쪽 패널의 두 번째 탭이다. "넓게 보기"를 누르면 전체 화면으로 연다.

**모양**
- 가운데에 지금 기록을 둔다.
- 1단계 연결을 종류별로 둘레에 부채꼴로 놓는다.
- "2단계"를 켜면 그 바깥 고리에 2단계 연결을 놓는다.
- 그리기는 직접 쓴 SVG로 한다. 그래프 라이브러리는 쓰지 않는다.
- 배치는 계산식(종류별 각도 구간 + 고리 반지름)으로 정한다. 힘 기반 배치는 쓰지 않는다. 같은 데이터면 항상 같은 그림이 나와야 사람이 기억한다. **[내 판단]**

**대표 지도: LOT 중심 (기존 "LOT Timeline"과 함께 쓴다)**
```
            [입고 LOT 협력사]
                  │
 [검사 IQC] ─ [LOT 2611-0042] ─ [작업 실적]
                  │        ╲
            [부적합 NC-…]  [출하 → 고객사]
                  │
               [CAPA]
```

**규칙**
- 점은 최대 60개다. 넘으면 종류별로 "+23"으로 접는다. 누르면 그 종류만 목록으로 연다.
- 점 색은 상태 색이다. 보류·부적합 열림은 빨간 테두리와 "보류" 글자를 함께 쓴다.
- 키보드:
  - 방향키로 점 사이를 옮긴다.
  - Enter로 그 기록을 연다.
  - Space로 그 점을 가운데로 다시 놓는다.
- 화면 낭독기용으로 같은 내용을 목록(`<ul>` 트리)으로 숨겨 둔다. "목록으로 보기" 단추로 눈에도 보이게 바꿀 수 있다.
- 지도를 SVG·PNG로 내려받는다. 심사 때 추적성 증빙으로 쓴다.

### U4. 저장된 보기 (목록 화면, P2 확장)

**모양**
- 목록 위에 보기 탭이 있다. 예: "전체 | 내 담당 | 이번 달 불합격 | + 보기".
- 보기 하나에 필터, 정렬, 보이는 칸, 칸 순서, 묶기(그룹) 기준, 표시 방식이 들어간다.
- 표시 방식은 표, 묶음 표, 칸반, 달력 중 하나다.
  - 칸반은 상태 칸이 있는 표에서만 쓴다.
  - 달력은 날짜 칸이 있는 표에서만 쓴다.

**새 모델 `core.SavedView`**
| 칸 | 형 | 설명 |
|---|---|---|
| target | →ContentType | |
| name | 글(40) | |
| owner | →User | 비우면 공용 보기 |
| shared | 예/아니오 | 공용 보기는 품질팀장·관리자만 만든다 |
| config | JSON | 필터, 정렬, 칸, 묶기, 방식 |
| sort | 정수 | |

**규칙**
- 필터 조건은 칸 종류에 맞게 고른다.
  - 글: 포함, 같음, 비어 있음
  - 수·날짜: 범위
  - 연결 칸: 그 기록 고르기
  - "오늘·이번 주·이번 달" 같은 상대 날짜
- 지금 보기 상태는 주소(`?view=` 또는 `?f=`)에 담는다. 주소를 복사해 남에게 그대로 보여줄 수 있다.
- 엑셀 내보내기는 지금 보이는 칸과 필터 그대로 내보낸다(P6).

### U5. 연결 칸 입력과 "새로 만들어 연결"

**연결 칸(→모델)**
- 검색 선택 창으로 고른다. 2글자부터 서버 검색을 하고 최근 쓴 5개를 먼저 보여 준다.
- 각 후보에는 번호, 이름, 상태 칩이 보인다. 예: "대한정밀 · 승인 · A".
- 고를 수 없는 후보는 회색으로 두고 이유를 적는다. 예: "거래 중지", "교정 만료", "보류 LOT".
  - 판단은 서버 `clean()` 규칙과 같은 함수로 한다. 화면은 미리 알려 주기만 하고, 최종 차단은 서버가 한다.

**새로 만들어 연결**
- 찾는 기록이 없으면 목록 맨 아래에 "'입력한 글'로 새 거래처 만들기"가 나온다.
- 누르면 작은 창에 그 표의 **필수 칸만** 나온다. 저장하면 바로 연결된다.
- 작은 창도 서버 검증을 똑같이 거친다. 권한이 없으면 이 항목은 보이지 않는다.

**연결 칩**
- 상세 화면 속성 블록 아래 한 줄에 정방향 연결을 칩으로 보인다.
- 칩에 마우스를 올리거나 키보드로 초점을 주면 그 기록의 요약 카드(핵심 속성 4개)가 뜬다.

### U6. 일괄 수정

**모양**
- 목록에서 여러 행을 고른다. 체크 칸, Shift+클릭, Ctrl+A를 쓴다.
- 아래에 동작 막대가 나온다: "12건 선택 · 칸 바꾸기 · 연결 · 엑셀 · 선택 해제".

**칸 바꾸기**
- 바꿀 칸 하나와 새 값을 고른다.
- 미리보기 표에 "지금 값 → 새 값"과 행별 검증 결과를 보여 준다.
- 저장은 한 트랜잭션으로 한다. 한 행이라도 `clean()`에 걸리면 아무것도 저장하지 않고 걸린 행을 보여 준다. **[내 판단]** 일부만 저장되면 무엇이 바뀌었는지 헷갈린다.

**막는 것**
- 승인 뒤 잠긴 기록, 판정이 끝난 검사, 보호 규칙에 닿는 칸(판정, 처분, 승인)은 일괄 수정 대상에서 뺀다.
- 고를 수 있는 칸 목록에서 아예 나오지 않는다. 서버도 거부한다.
- 이력에는 행마다 일반 수정과 똑같이 남는다.

### U7. 데이터 상태

기준정보가 비어 있거나 어긋난 곳을 한 화면에서 찾고 고친다.

**어디에 보이나**
- 목록 위에 작은 줄로 보인다. 예: "권장 칸 빈 행 34 · 연결 안 된 옛 글자 값 12 · 만료 임박 3".
- 누르면 그 조건으로 필터한 보기가 열린다.
- 관리자용 "데이터 상태" 화면은 표별 점수를 모아 보여 준다.

**세는 것**
| 항목 | 기준 |
|---|---|
| 필수 빈 칸 | 칸 설계의 **필** 칸이 비었다(필수 강제 전에 만든 옛 행) |
| 권장 빈 칸 | 칸 설계의 "권" 칸이 비었다 |
| 미정제 | 3.8 연결 칸이 비었는데 옛 글자 칸에 값이 있다 |
| 만료 임박 | 인증서, 거래처 인증, 교정, 문서 검토, 금형 수명 |
| 어긋남 | 계측기 `interval_days`와 개월 주기가 다르다(7.1), 불량 내역 합계가 실적 불량 수와 다르다 |

**규칙**
- 고치는 일은 그 기록 화면이나 일괄 수정(U6)으로 한다. 데이터 상태 화면에는 자동 수정 단추를 두지 않는다. 기존 데이터를 사용자 확인 없이 바꾸지 않기 위해서다.
- 판단 기준은 모델 메타(필수·권장 칸 목록)에서 읽는다. 새 표도 자동으로 들어간다.

### U8. 명령 팔레트 확장 (P1)

- **검색 대상:** 모든 레지스트리 표의 번호·이름. 기존 `core.search`를 넓힌다.
- **동작 명령:**
  - "새 부적합", "새 거래처"처럼 새 기록 만들기
  - "보기: 이번 달 불합격"처럼 보기 열기
  - "지도 열기"
  - "LOT 찾기"
- **문맥 명령:** 상세 화면에서 Ctrl+K를 누르면 "이 기록에 연결…", "이 LOT 보류 내역", "이 품번의 검사기준"이 먼저 나온다.
- **키 안내:** `?` 키로 단축키 목록 창을 연다.

### U9. 상세 화면 공통 틀 (P3 정리)

모든 표의 상세 화면을 같은 틀로 그린다. 새 표를 더할 때 화면 코드를 거의 쓰지 않기 위해서다.

**틀**
```
머리: 번호 · 제목 · 상태 칩 · [승인] [개정] [더 보기 ⋯]
속성 블록: 레지스트리가 정한 핵심 칸 8개 (2열)
연결 칩 줄
본문 탭: 상세(나머지 칸) | 하위 표들(예: 발주 품목) | 첨부
오른쪽: 연결 | 지도 | 이력 | 메모
저장 막대
```

**화면 정의**
- 표마다 서버에 짧은 화면 정의를 둔다: 핵심 칸, 하위 표, 칸 묶음.
- 정의가 없으면 모든 칸을 모델 순서대로 보인다.
- 사용자 정의 칸(칸 설계 2절)은 "상세" 탭 끝에 자동으로 붙는다.

**복잡한 화면은 지금처럼 따로 둔다**
- 검사 측정, 관리계획서처럼 업무 흐름이 복잡한 화면은 이 틀을 쓰지 않는다.
- 다만 오른쪽 패널은 공통으로 쓴다.

## 5. 접근성 (WCAG 2.2 AA)

| 항목 | 지킬 것 |
|---|---|
| 키보드 | 모든 동작을 키보드로 한다. 초점 순서는 머리 → 속성 → 본문 → 오른쪽 패널. 초점 테두리는 2px 이상이고 대비 3:1 이상(2.4.11, 2.4.13) |
| 단축키 | 한 글자 단축키는 입력 칸 밖에서만 동작한다. 설정에서 끌 수 있다(2.1.4) |
| 대비 | 글자 4.5:1, 큰 글자·아이콘 3:1. `fiori.css` 토큰으로 밝은·어두운 테마 둘 다 확인 |
| 색 | 상태는 색 + 글자(+ 모양)로 알린다. 지도 점도 같다 |
| 크기 | 누르는 대상은 최소 24×24px(2.5.8). 현장 태블릿 화면은 44px |
| 끌기 | 칸 순서 바꾸기, 칸반 옮기기는 끌기 말고 메뉴로도 할 수 있다(2.5.7) |
| 낭독기 | 연결 패널은 `<section aria-label>` + 묶음 제목 `<h3>`. 지도는 숨긴 목록 트리를 함께 둔다. 동작 결과는 `aria-live="polite"`로 알린다 |
| 인증 | 승인 서명의 비밀번호 칸은 붙여넣기와 비밀번호 관리자를 막지 않는다(3.3.8) |
| 확대 | 200% 확대와 320px 너비에서 가로 스크롤 없이 쓸 수 있다. 표는 표 안에서만 가로로 움직인다 |
| 움직임 | `prefers-reduced-motion`이면 지도 전환 효과를 끈다 |
| 언어 | `<html lang="ko">`. 오류 문구는 칸 바로 아래에 쓰고 무엇을 고칠지 적는다 |

## 6. 확장성 정리

| 하고 싶은 것 | 하는 일 | 개발자 필요 |
|---|---|---|
| 기존 표에 회사 고유 칸 더하기 | 관리 화면 "사용자 정의 칸" | 아니오 |

## 8. 구현 순서

화면은 데이터 단계를 따라간다. 표가 없으면 그 표의 화면도 없다.

| 순서 | 할 일 | 같이 가는 데이터 단계 |
|---|---|---|
| 1 | U1 관계 레지스트리 + U2 연결 패널 (기존 표만으로도 바로 쓸모가 있다) | A 직전 또는 A와 함께 |
| 2 | U5 연결 칸 입력·새로 만들어 연결, U9 상세 틀 | A (거래처·부서·직원) |
| 3 | U4 저장된 보기, U6 일괄 수정, U7 데이터 상태 | A 정제 작업과 함께 |
| 4 | U3 관계 지도, U8 팔레트 확장 | B·C (문서·조항 매트릭스) |
| 5 | 이후 단계의 새 표는 틀 위에 얹는다 | D~J |

단계마다 계획을 따로 쓰고, 계획마다 다음을 확인한다.
- 키보드 경로 e2e
- 권한 묶음 숨김 테스트
- 보호 규칙 칸이 일괄 수정에서 빠지는지

## 9. 범위 밖

- 실시간 동시 편집(여러 사람이 같은 기록을 동시에 고치는 것). 기존 저장 충돌 규칙을 유지한다.
- 모바일 전용 앱. 반응형 웹으로만 한다.
- 사용자가 직접 만드는 새 표(노코드 표 만들기). 사용자 정의 칸까지만 한다.
- AI 추천·자동 분류. 사용자가 뺐다.
