# QMS+MES 통합 업무 플랫폼 UX·구조 개선 설계서

작성 2026-11-02. 근거는 이 저장소의 코드(아래에 파일을 적음)와 공식 공개 자료다. 확인하지 못한 내용은 "확인 안 됨"으로 적었다.
우선순위: **P0** 즉시 개선해야 하는 사용성 문제 · **P1** 주요 업무의 접근성과 작업 효율 개선 · **P2** 데이터 분석 및 업무 통합 고도화 · **P3** 향후 MES/QMS 확장 기능.

## 1. 현재 시스템 구조 분석

- **앱 구성**: `core`(품번·BOM·라우팅·작업지시·실적·LOT·계보·부적합·보류·출하·삭제/수정 요청), `qms`(검사기준·검사·측정·SPC·계측기·자격·관리계획서·4M·클레임·SCAR·CAPA·문서·심사·PPAP·엑셀 양식·메모·대시보드), `personal`(연차·급여, 본인만). 화면은 Django 관리 화면(`BaseAdmin`) + 사용자 정의 화면 몇 개.
- **사용자 정의 화면**(`config/urls.py`): 내 할 일 `/todo/`, LOT 이력 `/trace/`, 부적합 간편 등록 `/nc/new/`, 검사 입력 `/inspect/`, SPC `/spc/<id>/`, 품질 KPI `/kpi/`, 협력사 평가 `/suppliers/`, 심사 자료 `/audit-pack/`, 메모 `/memo/…`, 엑셀 일괄 등록 `/import/`, 통합 검색 `/search/`, 연차·급여 `/me/`. 나머지 등록·조회는 `/admin/` 목록·변경 화면.
- **메뉴**: `core/nav.py`의 `NAV` 한 목록이 사이드바와 "전체 메뉴"(`core/admin.py` `grouped_app_list`)를 함께 만든다. `core/context_processors.py`의 `shell()`이 권한으로 항목을 거르고 현재 화면의 묶음을 연다.
- **대시보드**: `/todo/`는 사용자별 위젯 격자(`qms/widgets.py`, 기한 계산 `qms/due.py`). 개인 업무(승인 대기, 기한 임박 등) 중심.
- **권한**: 그룹 3종(`qms/apps.py` `ensure_roles`) — 품질엔지니어·품질팀장(core·qms 전체, 삭제 제외), 검사원(조회·검사·부적합 등록 위주). 화면은 `staff_member_required` + 뷰 안 `has_perm`, 관리 화면은 `has_*_permission`.
- **업무 규칙**: `docs/business-rules.md`. 이번 개선은 이 규칙의 코드(모델 `clean()/save()`, 서버 뷰)를 바꾸지 않는다.

## 4. 권장 전체 메뉴 구조 (구현됨, P0)

`core/nav.py` `NAV`만 바꿨다. URL·권한은 그대로이고 각 기능은 한 묶음에만 둔다. 사이드바와 전체 메뉴가 같은 순서다.

1. **통합 업무 홈**: 내 할 일, 공장 종합현황(신규), 미분류 메모, 연차·급여
2. **생산관리 (MES)**: 작업지시, 작업 실적, LOT, LOT 이력 조회, 출하
3. **품질관리 (QMS)**: 검사 입력, 수입검사, 공정검사, 출하검사, 계측기·교정, 검사원 자격
4. **품질보증 및 개선**: 부적합 등록, 부적합, 보류, CAPA(시정조치), 4M 변경, 문서, 내부심사, 심사 체크리스트·증적, 심사 자료 출력
5. **고객 및 협력사**: 고객 클레임(8D), SCAR, PPAP, 협력사 평가
6. **분석 및 보고서**: 품질 KPI, 엑셀 보고서 양식
7. **기준정보 및 시스템 관리**: 품번·BOM·라우팅, 공정, 검사기준, 관리계획서, 고객사별 8D 기한, 엑셀 일괄 등록, 사용자, 전체 메뉴

통합 업무 홈은 항상 펼쳐 두고, 현재 화면이 속한 묶음도 펼친다. 브라우저에 저장된 묶음 열림 상태(`qms.nav.open`)는 묶음 이름 기준이라 이름이 바뀐 묶음은 기본값으로 돌아간다(데이터 영향 없음).

## 5. 권장 대시보드 구조 (구현됨, P0)

- **내 할 일 `/todo/`**: 그대로 유지(개인 위젯). 머리에 "공장 종합현황" 버튼을 추가.
- **공장 종합현황 `/overview/`** (`qms/views.py` `overview`, `qms/templates/qms/overview.html`): DB 기록만 집계하고 설비 실시간 값은 없다. 카드는 그 목록의 조회 권한이 있을 때만 보인다.

| 섹션 | 카드 | 값 | 누르면 |
| --- | --- | --- | --- |
| 생산 현황 | 진행 중 작업지시 | 상태별 건수, 진행 중 최대 10건과 진도율(`WorkOrder.progress`) | 작업지시 목록 `?status__exact=RUNNING` |
| | 계획 대비 실적 | 이번 달 납기 작업지시의 계획 수량 합 대비 마지막 공정 양품 합 | 작업지시 목록(이번 달 납기) |
| | 생산 수율 | 이번 달 작업 실적 양품 ÷ 투입, 낮은 공정 5개 (`kpi.process_yield`) | 작업 실적 목록 |
| 품질 현황 | 검사 불합격 | 이번 달 판정 건수·불합격 건수, 검사 구분별 | 검사 목록 `?result__exact=FAIL` |
| | 보류 LOT | 풀리지 않은 보류의 LOT 수 | 보류 목록 `?released_at__isnull=True` |
| | 열린 부적합 | 종결 전 부적합 | 부적합 목록 `?closed_at__isnull=True` |
| | 진행 중 CAPA | 진행 건수, 기한 초과·유효성 확인 대기 | CAPA 목록 |
| | 계측기 교정 | 14일 안에 기한이 오거나 지난 계측기 | 계측기 목록 |
| | SPC 경보 | 최근 7일 경보(`recent_spc_alarms`) | 해당 관리도 `/spc/<id>/` |
| | 협력사 품질 | 최근 3개월 실적 있는 협력사, 불합격률 높은 순 (`kpi.suppliers`) | 협력사 평가 `/suppliers/?months=3` |

볼 수 있는 카드가 하나도 없으면 빈 상태 안내("관리자에게 조회 권한을 요청하세요")를 보인다. 생산계획 모델이 없으므로 "계획"은 작업지시 계획 수량이라고 카드에 적었다.

## 7. 화면 간 이동 및 업무 흐름 설계

정상 흐름과 이상 흐름 모두에서 각 단계 화면이 다음·이전 단계로 링크된다. 굵은 글씨가 이번에 추가된 연결이다.

- **정상 흐름**: 검사 입력(입고 등록 → 수입검사 판정) → LOT 상세(**작업지시·검사·출하 관련 기록**) → 작업지시 상세(**LOT·작업 실적·검사·부적합**) → 작업 실적(**작업지시·LOT 이력**) → 출하 상세(**LOT 이력·부적합**).
- **이상 흐름**: 검사 불합격 → 부적합 자동 등록(기존) → 부적합 상세(**원 검사·보류·고객 클레임·SCAR·LOT 이력**, 기존 CAPA 만들기) → 보류 상세(**부적합·LOT 이력**) → CAPA(기존 출처 기록 링크) → 유효성 확인 → 종결.
- **현황에서 시작**: 공장 종합현황 카드 → 조건이 걸린 목록 → 상세 → 관련 기록.

관련 기록의 "전체 보기"는 관리 목록이 받는 한 단계 조건(`lot__id__exact` 등)만 쓴다. 작업지시 → 검사·부적합처럼 두 단계 관계는 관리 화면이 조건을 막으므로 건수와 최근 5건만 보인다.

## 8. 사용자 역할별 접근 방식

권한 정의(`ensure_roles`)는 바꾸지 않았다. 새 화면·링크는 기존 권한으로 거른다.

| 역할 | 공장 종합현황에서 보이는 카드 | 관련 기록 |
| --- | --- | --- |
| 품질팀장·품질엔지니어 | 전부 | 전부 |

## 9. 기존 DB 및 기능 재사용 방안

- 모델·마이그레이션 변경 없음(`makemigrations --check --dry-run` → "No changes detected").
- URL 삭제·변경 없음. `/overview/` 하나만 추가. `/`는 계속 `/todo/`.
- 인터록·처분·승인 잠금·삭제/수정 요청·검사 판정·교정·4M·SPC·개인자료 코드는 건드리지 않았다. 관련 기록 칸은 읽기 전용 링크이고, 링크한 관리 화면이 다시 권한을 검사한다.
- 기존 테스트를 유지하고 메뉴 이름이 바뀐 테스트 2개만 새 이름으로 고쳤다. 새 테스트는 `qms/tests.py` `OverviewTest`.

## 11. 예상되는 기술적 위험 및 대응 방안

| 위험 | 내용 | 대응 |
| --- | --- | --- |
| 익숙한 메뉴 위치 변경 | 묶음 이름·순서가 바뀌어 기존 사용자가 메뉴를 다시 찾아야 함. 저장된 묶음 열림 상태(`qms.nav.open`)도 초기화됨 | URL은 그대로라 즐겨찾기는 동작. 통합 검색(`/search/`)과 전체 메뉴로 찾을 수 있음. 배포 시 새 묶음표를 공지 |
| 권한 노출 | 새 카드·링크가 볼 권한 없는 기록을 보일 위험 | 카드·관련 기록 모두 `has_perm('앱.view_모델')`로 거르고, 링크 대상 관리 화면이 다시 권한을 검사. `OverviewTest`가 검사원·그룹 없는 계정으로 확인 |
| 관리 목록 조건 차단 | 두 단계 조건(`lot__work_order__id__exact`)은 관리 화면이 막아 `?e=1`로 돌려보냄 | 그런 묶음은 "전체 보기" 링크를 만들지 않고 건수·최근 5건만 표시. 링크 URL이 200인지 테스트로 확인 |
| 성능 | 공장 종합현황은 카드마다 집계 쿼리, 관련 기록은 묶음마다 쿼리 1~2개. 계측기 카드는 활성 계측기를 파이썬에서 거름 | 목록은 최대 10건(작업지시)·5건(관련 기록)만 가져오고 6건 이상일 때만 `count()`. 데이터가 크게 늘면 계측기 기한을 DB 조건으로 옮기는 것을 검토 (P2) |
| 데이터 오해 | 생산계획 모델이 없어 "계획 대비 실적"이 작업지시 계획 수량 기준. 생산 수율은 이번 달 실적만 집계해 월초에는 비어 보일 수 있음 | 카드 안에 계산 기준을 적음. 생산계획 모델은 P3 |
| 업무 규칙 약화 | 화면 변경 중 인터록 코드가 바뀔 위험 | 모델 `clean()/save()`·서버 뷰의 규칙 코드를 수정하지 않음. 기존 테스트 전체와 `scripts/e2e_check.py`로 인터록 동작 확인 |
| 오프라인·의존성 | 새 라이브러리·CDN 추가 시 사내 오프라인 환경에서 깨짐 | 새 의존성 없음. CSS는 기존 `fiori.css` 토큰만 사용 |

효과 수치(클릭 수 감소율, 처리 시간)는 측정하지 않았다. 도입 후 실제 사용자 관찰로 확인해야 한다.
