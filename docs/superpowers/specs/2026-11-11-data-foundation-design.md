# 기준정보·업무 데이터 확장 설계 (초안)

- 작성일: 2026-11-11
- 상태: 사용자 검토 대기
- 근거: 사용자가 보낸 개발 단계 그림(①요구사항 분석 ~ ⑳모니터링)과 계측기 항목 표(2-1~3-3). 회사 양식은 없다고 하여, 항목은 IATF 16949·ISO 9001·ISO 10012의 일반 관행을 바탕으로 한 **초안**이다. 사용자가 필수/선택을 확정해야 한다.

## 1. 왜 하는가

현재 모델은 기록 칸이 너무 적다. 2026-11-11 실측 결과는 아래와 같다.
- 품번 3칸, 공정 2칸, 계측기 6칸, 검사 6칸이다.
- 협력사·고객사·심사원·피심사 부서는 글자 칸이다(`core/models.py` `Lot.supplier`, `Shipment.customer`, `qms/models.py` `Scar.supplier`, `CustomerRule.customer`, `InternalAudit.auditor/auditee` 등).

그래서 같은 거래처가 여러 이름으로 갈라진다. 협력사별·부서별 집계도 믿을 수 없다. 칸을 늘리기 전에 기준정보(거래처·사업장·부서·직원)를 먼저 세운다.

| 단계 | 이 시스템에서 | 이번 범위 |

## 3. 원칙

- 기존 데이터는 지우지 않는다. 새 칸은 비어도 되는 칸으로 추가한다.
- 기존 글자 칸(`supplier`, `customer` 등)은 남긴다. 옆에 거래처 연결 칸을 새로 둔다. 연결 칸을 채우는 정제 작업은 기존 행의 값을 바꾸므로 **실행 전 사용자 승인**을 받는다. 정제 전에 `backup`을 실행한다.
- 필수 항목은 새로 등록하거나 고칠 때부터 `clean()`에서 강제한다. 옛 기록은 열람·출력에 막히지 않는다.
- 보호 규칙(LOT 보류, 교정 인터록, 검사 판정, 승인 서명, 본인 열람)은 바꾸지 않는다.
- 모든 새 모델은 `history = HistoricalRecords()`, 한국어 `verbose_name`, `BaseAdmin`을 쓴다. 삭제는 시스템 관리자만 한다.
- 화면은 탭으로 나눈다(기본 / 상세 / 첨부 / 이력). 기본 탭의 필수 칸만 채워도 저장된다.

## 4. 항목 (① 요구사항 초안)

표기: **필**=필수, 권=권장, 조=조건부, 선=선택.

### 4.1 새 마스터

**사업장 `Site`**
- 코드 **필**, 이름 **필**, 주소 권, 전화 선, 사용 여부 **필**

**부서 `Department`**
- 코드 **필**, 이름 **필**, 사업장 **필**, 상위 부서 선, 부서장(사용자) 권
- 문서번호 부서 코드(`CodeValue` 부서 묶음) 연결 조: 문서 번호를 매기는 부서만
- 사용 여부 **필**

**직원 정보 `Employee`** (사용자 1명당 1행)
- 사용자 **필**, 사번 권, 부서 **필**, 직위 권, 직무 선, 내선·휴대전화 선, 사용 여부 **필**
- 입사일은 `personal.LeaveProfile.hired_on`에 있으므로 중복하지 않는다.

**거래처 `Partner`**
- 기본: 거래처 코드 **필**(자동), 상호 **필**, 구분 **필**(협력사 / 고객사 / 외주가공 / 교정기관 / 기타, 여러 개 가능), 사업자등록번호 권, 대표자 선
- 연락: 주소 권, 대표전화 권, 대표 이메일 선, 담당자 이름·전화·이메일 권
- 품질: 거래 상태 **필**(신규 평가 / 승인 / 조건부 승인 / 거래 중지), 품질인증(ISO 9001·IATF 16949 등) 선, 인증번호 선, 인증 유효기한 조(인증이 있으면), 최근 평가일 선, 평가 등급 선
- 승인: 승인자·승인일(기존 승인 서명 방식)
- 첨부: 사업자등록증, 인증서, 평가표
- 비고 선, 사용 여부 **필**

**승인 협력사 품목 `ApprovedSource`** (IATF 8.4 승인 공급자 목록)
- 거래처 **필**, 품번 **필**, 승인일 권, 상태 **필**(승인 / 조건부 / 중지), 근거(PPAP·초품 등) 선, 비고 선

**공통 첨부 `Attachment`**
- 대상(모델·행) **필**, 종류 **필**(사진 / 사양서 / 매뉴얼 / 구매서류 / 성적서 / 보증서 / 기타), 파일 **필**, 설명 선, 올린 사람·일시 자동
- 접근 권한은 대상 기록의 열람 권한을 따른다(기존 첨부 접근 제어와 같게).

### 4.2 기존 모델 보강

**품번 `Item`** (현재: 코드, 이름, 구분)
- 규격 권, 단위 **필**(기본 EA), 재질 선, 도면번호·도면 개정 권, 고객사(거래처) 조(완제품), 고객 품번 조(완제품), 기본 협력사(거래처) 조(구매품), 중량 선, 수입검사 대상 여부 조(구매품), 사진 선, 사용 여부 **필**, 비고 선

**공정 `Process`** (현재: 코드, 이름)
- 공정 구분 권(가공 / 조립 / 검사 / 포장 / 외주), 담당 부서 권, 라인 선, 외주 거래처 조(외주일 때), 사용 여부 **필**, 비고 선

**입고 LOT `Lot`** (구매품 LOT일 때)
- 협력사(거래처) **필**, 발주번호 권, 납품서(거래명세서) 번호 권, 입고일 **필**, 입고 수량 **필**(기존 `qty`), 협력사 LOT 번호 권, 제조일 선, 유효기한 조(유효기한 있는 자재), 협력사 성적서(CoA) 첨부 권, 입고 담당자 권

**검사 `Inspection`** (현재: LOT, 기준, 일시, 검사자, 판정, 부적합)
- 검사 수량(로트 크기) **필**, 시료 수 **필**, 합격 수량·불합격 수량 조(판정 시), 검사 수준 선(보통 / 강화 / 완화), 성적서 확인 여부 조(수입검사), 판정 의견 선, 검토자·검토일 선, 첨부(사진·성적서) 선
- 판정 후 수정 불가 규칙은 새 칸에도 적용한다.

**계측기 `Gauge`** — 사용자 표 2-1~2-7을 그대로 따른다. 거래처·부서·사업장·관리자는 4.1 마스터를 연결한다.
- 기존 `number`=관리번호, `name`=장비명, `interval_days`·`last_calibrated`=교정 주기·최근 교정일로 쓴다.
- 등록 승인(`approval_status`)은 기록용으로만 둔다. 측정 사용 가능 여부(`usable_on`)는 지금 규칙 그대로다. 승인을 사용 조건에 넣으려면 별도 승인을 받는다.

**교정 이력 `CalibrationRecord`** — 표 3-1 그대로
- 저장하면 계측기의 `last_calibrated`를 갱신한다. 불합격이면 계측기를 사용 중지한다. 이 동작은 인터록을 강화하는 방향이다.

**수리·점검 이력 `MaintenanceRecord`** — 표 3-2 그대로

**변경 이력(표 3-3)** — simple-history가 이미 남긴다. 변경 사유는 기존 수정 요청(`RevisionLog`) 흐름을 쓴다. 새 표를 만들지 않는다.

**거래처 연결만 추가하는 모델**
- `Shipment.customer`, `CustomerRule.customer`, `CustomerClaim.customer`, `PpapSubmission.customer` → 고객사
- `Scar.supplier` → 협력사
- `InternalAudit.auditee` → 부서, `auditor` → 사용자(외부 심사원이면 글자 그대로)

## 5. 구조 (③)

- 사업장·부서·직원·거래처·승인 협력사 품목·공통 첨부는 `core` 앱에 둔다. 여러 앱이 같이 쓰기 때문이다.
- 교정·수리 이력은 `qms` 앱의 계측기 옆에 둔다.
- 권한은 `ensure_roles`에 새 모델의 view/add/change를 기존 역할 기준으로 추가한다. 거래처·부서 편집은 품질팀장·시스템 관리자만 한다. 이것은 권한 변경이므로 구현 전에 표로 승인을 받는다.
- API는 기존 `core/api` 방식(목록·상세·옵션)을 따른다. 화면은 React 기준정보 메뉴에 넣는다.
- 엑셀 일괄 등록 대상에 거래처·부서·직원·계측기를 추가한다.

## 6. 순서 (②)

각 단계는 따로 배포할 수 있다. 단계마다 테스트를 통과한 뒤 다음으로 넘어간다.

1. 사업장·부서·직원·거래처 마스터 + 화면 + 엑셀 등록
2. 기존 글자 값 → 거래처·부서 연결(정제). **실행 전 승인, 백업 필수**
3. 입고 LOT·수입검사 보강
4. 계측기 보강 + 교정·수리 이력
5. 품번·공정 보강, 승인 협력사 품목
6. 나머지 모델의 거래처 연결(SCAR, 클레임, PPAP, 출하, 내부심사)

## 7. 범위 밖

- ⑪~⑮ AI 기능(Vector DB, Graph DB, RAG, LLM, Agent). 새 의존성, 외부 모델, 오프라인 동작, 데이터 유출 위험을 따로 결정해야 한다.
- ⑰ ERP 연동. 대상 시스템이 정해지지 않았다.
- 설비·금형 마스터, 재고 수불. 요청이 오면 같은 방식으로 추가한다.

## 8. 사용자가 확인할 것

- 3절의 정제 작업(2단계) 실행 여부
- 5절의 거래처·부서 편집 권한
- 7절 AI 단계의 진행 여부
