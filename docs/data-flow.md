# 데이터 들여오기·내보내기 (PC ↔ 서버)

사람이 PC의 파일(CSV·엑셀)을 서버에 올리고, 서버의 기록을 파일로 받는 흐름을 정한다. 2026-11-20 코드 기준으로 확인했다. 들여오기 기능을 바꾸면 이 문서도 함께 고친다.

## 1. 원칙

1. **원본은 서버 DB 한 곳이다.** PC 파일은 들여오기 전 원자료이거나 받은 사본이다. 사본을 고쳐 다시 올리는 왕복은 두지 않는다. 기록 수정은 화면 안에서 한다.
2. **사람이 직접 올리고 받는다.** 화면에서 파일을 고르고 「확정」을 누를 때만 저장한다. 폴더 자동 감시, 자동 업로드, PC와의 동기화는 두지 않는다.
3. **표 데이터는 CSV가 표준이다.** 엑셀(.xlsx)도 받는다. CSV 글자 인코딩은 UTF-8(BOM 있어도 됨)을 쓰고, 읽지 못하면 CP949(한국어 엑셀 저장)로 읽는다.
4. **미리보기 → 확정.** 미리보기는 저장 없이 모든 행을 검사해 오류를 행 번호와 함께 보여 준다. 확정은 한 행이라도 틀리면 전체를 되돌린다(전부 또는 없음).
5. **모델 검증과 업무 규칙 함수를 거친다.** 행마다 `full_clean()` → `save()`, 판정·입고처럼 규칙 함수가 있는 기록은 그 함수(`submit_inspection`, `receive_lot` 등)를 부른다. DB에 직접 넣지 않는다(2절).
6. **변경 이력이 남는다.** `save()`를 거치므로 simple-history가 행마다 이력을 쓴다.
7. **원본 파일을 남긴다.** 확정한 파일은 원자료 증거로 보관하고, 누가·언제·어떤 파일로·몇 건을 들였는지 기록한다(3단계에서 만든다, 4절).
8. **권한은 서버에서 확인한다.** 대상 기록의 추가(`add_`)와 변경(`change_`) 권한이 모두 있어야 한다. 기존 행을 덮어쓸 수 있기 때문이다.
9. **꺼진 모듈로는 들여오지 않는다**(MOD-12).
10. **표가 아닌 파일**(PDF, 사진, 도면, 메일)은 데이터가 아니라 기록의 첨부(`Attachment`)로 올린다.

## 2. DB에 직접 넣지 않는 이유

PostgreSQL `COPY`나 pgAdmin으로 CSV를 테이블에 바로 넣으면 아래가 모두 빠진다.

| 빠지는 것 | 결과 |
| --- | --- |
| 인터록(`clean()`): 보류 LOT 출하·실적 차단, 교정 기한 지난 계측기 거부, 검사원 자격, 승인된 검사기준만 | 규칙을 어긴 기록이 들어간다 |
| 변경 이력(simple-history) | 누가 무엇을 바꿨는지 남지 않는다(IATF 기록 관리) |
| 자동 처리: 번호 매기기, 판정, 불합격 → 부적합 등록 → 보류 | 판정 없는 검사, 보류 안 된 불합격 LOT이 생긴다 |
| 코드 → id 변환 | CSV는 품번·거래처 코드를 쓰고 DB는 id를 쓴다 |
| 권한 확인 | 권한 없는 사람의 데이터가 들어간다 |

성능은 문제가 아니다. 수천 행은 ORM으로 충분하다. `COPY`가 의미 있는 규모(수십만 행)는 이 시스템의 업무 기록에 없다.

## 4. 빈 곳 (3단계에서 채운다)

1. **들여오기 대상이 두 종류뿐이다**(`core/importer.py` `HANDLERS`). 나머지 기록은 화면에서 한 건씩 넣는다.
2. **빈 양식이 없다.** 들여오기 전에 「엑셀 가져오기 설정」에서 열을 짝지어야 한다. 표준 열 이름(5절)을 쓰면 설정 없이 받을 수 있다.
3. **측정 원자료는 폴더 수집뿐이다.** 화면에서 올리는 길이 없다. 그리고 `ingest`는 검사원을 비워 둔다. 그래서 자격 기록이 하나라도 있는 검사 구분은 `Inspection.finalize`가 거부한다. 계측기도 적지 않는다(설비 수집이라 일부러 뺐다, `submit_inspection` 주석).
4. **원본 파일과 들여오기 기록이 남지 않는다.** 행 이력은 남지만 어느 파일에서 왔는지 모른다.

## 5. CSV 표준

### 공통

- 1행은 열 제목, 2행부터 데이터. 빈 행은 건너뛴다.
- 열 제목은 「새로 만들기」 화면의 칸 이름과 같다. 3단계에서 종류별 빈 양식을 화면에서 받게 한다.
- 다른 기록을 가리키는 칸은 id가 아니라 사람이 읽는 키를 쓴다. 품목은 품번, 거래처는 거래처 코드, LOT은 LOT 번호, 작업지시는 작업지시 번호, 계측기는 관리번호, 부서는 부서 코드, 사용자는 로그인 아이디를 쓴다.
- 날짜는 `YYYY-MM-DD`, 일시는 `YYYY-MM-DD HH:MM`. 숫자는 소수점 `.`, 천 단위 쉼표 없이 쓴다.
- 예/아니오 칸은 `예`·`아니오`로 쓴다. `Y`·`N`, `1`·`0`도 받는다.
- 빈 칸은 값 없음이다.
- **키 열**(아래 표 굵은 칸) 값이 이미 있으면 그 기록을 고치고, 없으면 새로 만든다. 키 열이 없는 종류는 늘 새로 만든다.
- 하위 기록(심사 발견사항, 심사 항목, 생산실적)은 부모 기록 화면에서 올린다. 그래서 부모 칸은 파일에 없다.

`*`는 필수. 칸 목록은 `core/recordspec.py` `SPECS`의 `create`와 같다.

| 검사원 자격 | 검사원(아이디)*, 검사 구분*, 유효기한*, 근거* |

체크리스트 이름처럼 유일하지 않은 키가 두 건 이상 맞으면 그 행은 오류로 돌려준다.

### 측정 원자료

검사 1건 = 같은 파일 안의 같은 (LOT, 검사 구분) 행 묶음. `collect`와 같은 형식에 두 열을 더한다.

| 열 | 내용 |
| --- | --- |
| `lot`* | LOT 번호 |
| `type`* | `INCOMING`/`PROCESS`/`OUTGOING` 또는 수입검사/공정검사/출하검사 |
| `characteristic`* | 검사항목 이름(승인된 현재 검사기준의 항목) |
| `value`* | 계량형은 숫자, 계수형은 `OK`·`1`·`PASS`·`합격`이면 합격 |
| `gauge` | 계측기 관리번호. 비면 검사 입력 화면과 같이 맞는 계측기를 자동으로 고른다 |

화면에서 올리면 올린 사람이 검사원이 되고 `submit_inspection`으로 판정한다. 따라서 자격, 계측기 필수, 교정 기한, 불합격 → 부적합 → 보류가 화면 입력과 똑같이 걸린다. 폴더 수집(`collect`)은 지금 그대로 둔다.

## 6. 들여오지 않는 것

| 기록 | 이유 |
| --- | --- |
| 보류 | 부적합 등록으로만 생기고 처분으로만 풀린다 |
| 승인·서명·판정·종결 칸 | 비밀번호 재입력 서명과 판정 경로로만 바뀐다(`SIGN_FIELDS`) |
| 변경 이력 | 시스템이 쓴다 |
| 개인 연차·급여 | 본인만 열람한다 |
| 사용자·권한·모듈 설정, 채번 규칙, 사용자 정의 필드, 가져오기 설정, 엑셀 양식 | 보안·설정이라 화면에서 한 건씩 한다 |
| 부적합 | 지금은 부적합 등록 화면에서만. 들여오려면 `save_quick_nc`를 행마다 불러야 한다 — 필요해지면 따로 정한다 |
| 검사기준·관리계획서 | 개정·승인 흐름이 있는 문서. 항목은 화면 표에 붙여 넣는다 |

## 7. 3단계 구현 순서

한 단계씩 테스트 먼저 쓰고 끝낸다.

1. **대상 일반화.** `SPECS`의 `create` 칸으로 들여오기 대상을 만든다. 키 열로 고치거나 만들고, 외래키는 5절 키로 찾는다. 완료: 5절 종류 전부 미리보기·확정 테스트, 권한 없는 사용자 403, 꺼진 모듈 거부, 보류 LOT 출하 행 오류.
2. **빈 양식 받기.** 종류마다 표준 열 제목만 있는 CSV를 화면에서 받는다. 그 양식은 설정 없이 들여온다. 완료: 받은 양식을 채워 올리면 그대로 들어간다.
3. **측정 원자료 화면 업로드.** 5절 형식, `submit_inspection` 경유. 완료: 합격·불합격(→ 부적합·보류), 자격 없음, 교정 기한 지남, 없는 검사항목이 화면 입력과 같은 결과.
4. **원본 파일·들여오기 기록.** 확정한 파일을 보관하고 누가·언제·파일·대상·건수를 남긴다. 완료: 기록 목록에서 원본 파일을 받을 수 있다.

## 8. 정할 것

- 원본 파일 보관 위치와 보관 기간(첨부 폴더 `data/attachments/`를 쓸지).
- 들여오기 기록의 열람 권한(시스템 관리자만, 또는 해당 기록 열람 권한자).
