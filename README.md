# QMS+MES (localhost)

품질엔지니어 1인이 어느 회사에서든 다시 세울 수 있는 QMS+MES 틀. 비용 0원(Python, Django, SQLite).

## 처음 설치

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
.\.venv\Scripts\python manage.py migrate
.\.venv\Scripts\python manage.py createsuperuser
```

## 실행

프로젝트 폴더의 **`서버시작.bat`을 더블클릭**하면 DB 갱신(migrate) 후 서버가 켜지고 브라우저가 열립니다. 끌 때는 그 검은 창에서 `Ctrl+C`를 누르거나 창을 닫습니다.

터미널에서 직접 켤 때:

```powershell
.\.venv\Scripts\python manage.py runserver
```

http://127.0.0.1:8000/ → **내 할 일** 화면이 열립니다.

왼쪽 메뉴는 업무 영역별 7묶음(통합 업무 홈 · 생산관리 (MES) · 품질관리 (QMS) · 품질보증 및 개선 · 고객 및 협력사 · 분석 및 보고서 · 기준정보 및 시스템 관리)으로 나뉘어 있고, 권한이 있는 항목만 보입니다(설계 근거 `docs/ux-improvement-plan.md`). 묶음 제목을 누르면 접고 펼 수 있고, 펼쳐 둔 상태는 그 PC 브라우저에 기억됩니다. 전체 메뉴(`/admin/`)도 같은 묶음으로 정렬됩니다.

### 새 화면 `/app/` (React, 시범)

`/app/`은 React로 만든 새 화면입니다. 지금은 **내 할 일**(`/app/todo`), **공장 종합현황**(`/app/overview`), **검사기준서**(`/app/specs`), **검사 입력**(`/app/inspect`), **검사 목록·성적서**(`/app/inspections`), **기준정보**(품번·공정·관리계획서·고객사별 8D 기한·엑셀 일괄 등록), **LOT 이력**(`/app/trace`), **미분류 메모**(`/app/memos`), **감사 기록**(`/app/audit`)을 옮겨 두었고, 기존 `/todo/`·`/overview/`와 관리 화면은 그대로 있습니다. 로그인은 기존과 같은 계정을 쓰며, 카드나 줄을 누르면 기존 화면으로 이동합니다. 설계와 단계는 `docs/architecture-migration-plan.md`에 있습니다.

운영 PC에서는 아무것도 더 할 일이 없습니다. 빌드된 파일(`frontend/dist/`)이 저장소에 들어 있어서 `서버시작.bat`이나 `scripts\serve.ps1`로 켜면 그대로 열립니다. **운영 PC에서는 Node.js도 빌드도 필요 없습니다.**

화면을 고치는 개발 PC에서만 Node.js가 필요합니다.

```powershell
cd frontend
npm ci            # 처음 한 번 (패키지 설치)
npm run dev       # 개발 서버: http://localhost:5173/app/ (Django는 127.0.0.1:8000에서 따로 켜 둡니다)
npm run build     # 결과를 frontend\dist\에 만듭니다. 화면을 고쳤으면 이 폴더도 함께 커밋합니다
```

개발 서버 주소는 `127.0.0.1`이 아니라 `localhost`로 엽니다.

#### 검사기준서 `/app/specs`

- **목록:** 품번·검사 구분·상태로 거르고 "엑셀로" 링크로 목록을 `.xlsx`로 받습니다. "새 기준서"는 품번과 검사 구분을 골라 Rev.1 초안을 만듭니다(품번·구분은 만들 때만 고릅니다).
- **기록 페이지(`/app/specs/:id`):** 검사항목을 표에서 고칩니다. 엑셀에서 복사한 칸을 붙여 넣을 수 있고(천 단위 쉼표·공백은 정리, 빈 칸은 규격 없음), `Ctrl+S`로 저장합니다. 저장은 전부 되거나 하나도 안 됩니다. 오류는 그 칸에 표시됩니다. 다른 사람이 먼저 고쳤으면 `다른 사람이 먼저 고쳤습니다. 다시 불러오세요.`가 나옵니다.
- **저장 전 변경이 있으면** "승인 서명"과 "이력 남기기"는 눌러지지 않습니다. 먼저 저장하세요.
- **승인:** "승인 서명"은 품질팀장이 비밀번호를 다시 입력해 승인합니다. 승인된 기준서는 읽기 전용이며 "새 개정"으로 다음 개정 초안을 만듭니다(항목 복사). "이전 개정과 비교"는 바뀐 항목을 색으로 보여 줍니다.
- **개정 이력:** "이력 남기기"로 변경 내용과 사유를 신청하면 "대기"이고, 품질팀장이 비밀번호로 확정하면 더는 고칠 수 없습니다.
- **삭제 버튼:** 표의 줄 삭제 버튼은 품질엔지니어·품질팀장에게는 보이지 않습니다(두 역할에 `delete_characteristic` 권한이 없습니다).
- **샘플링:** 샘플링 칸은 목록(예: 전수검사, n=5, AQL)에서 고르고, 목록에 없을 때만 직접 입력합니다.
- **메모 탭:** 검사기준서에는 메모를 직접 붙일 수 없어서 미분류 메모(`/app/memos`)로 연결됩니다.
- **내보내기·PDF:** "내보내기"는 문서를 `.xlsx`(A4 한 시트)로 받습니다. "PDF"는 인쇄 화면(`/app/specs/:id/print`)을 열고, 브라우저의 "인쇄 / PDF로 저장"으로 만듭니다. 승인 전 문서에는 `초안 — 승인 전` 표시가 들어갑니다.
- **Ctrl+K:** 어느 화면에서나 명령창이 열려 기록을 찾아 이동합니다(결과가 없으면 이동하지 않습니다).

#### 검사 입력 `/app/inspect`

- **스캔:** LOT 번호를 스캔하거나 입력하고 Enter를 누르면 그 LOT에 맞는 검사 버튼(수입·공정·출하)이 나옵니다. 아래 표는 아직 검사하지 않은 LOT(검사 대기)입니다.
- **LOT 찾기:** 번호를 모르면 번호·품번·품명·협력사 일부를 입력합니다. 맞는 LOT이 목록으로 나오고(보류 LOT은 `보류` 표시), 고르면 바로 조회됩니다.
- **없는 LOT:** 등록되지 않은 번호면 "입고 등록" 창이 열립니다. 품목과 입고수량을 넣고 저장하면 바로 수입검사를 시작할 수 있습니다.
- **측정(`/app/inspect/:lot/:spec`):** 승인된 현재 검사기준의 항목이 표로 나옵니다. 계측기를 고르고 값을 넣으면 즉시 `합격`/`규격 이탈`이 표시되고, Enter로 다음 칸으로 갑니다. "판정"은 기존 화면과 같은 규칙(검사원 자격·계측기 교정 기한·승인된 기준)으로 전부 저장되거나 하나도 저장되지 않습니다. 두 번 눌러도 1건만 저장됩니다. 불합격이면 부적합 번호가 표시되고 LOT이 보류됩니다. 즉시 확인이 끝나기 전에 판정을 눌렀는데 불합격 항목이 있으면, 저장하지 않고 불량유형 칸을 먼저 보여 줍니다. 이미 판정한 LOT은 처분 전 부적합이 있을 때(재작업·수리 후 재검사)만 열리고, 이때 경고가 나오며 판정 때 "재검사로 판정할까요?"를 한 번 더 묻습니다. 보류 중인 LOT이면 "합격해도 보류는 부적합 처분 때 풀립니다" 경고가 나옵니다. 계측기를 하나라도 등록했으면 계량형 항목은 계측기를 골라야 판정됩니다. 최신 승인 개정이 아니거나 품번이 다른 기준으로는 화면이 열리지 않습니다.
- 기존 `/inspect/` 화면도 그대로 있습니다.

#### 검사 목록·성적서 `/app/inspections`

- **목록:** 수입·공정·출하 탭(`?tab=INCOMING|PROCESS|OUTGOING`)과 검색으로 거르고 "엑셀로"로 `.xlsx`를 받습니다. 판정은 합격·불합격·미판정으로 표시됩니다. 위쪽 요약에 지금 탭·검색 기준의 전체·합격·불합격 건수와 합격률(판정된 검사만 분모)이 나옵니다.
- **기록 페이지(`/app/inspections/:id`):** 검사 결과와 측정값을 읽기 전용으로 봅니다(판정 후에는 고칠 수 없습니다). 오른쪽 메모 칸에서 이 검사에 메모·사진을 바로 남깁니다(품번 기록 페이지도 같습니다).
- **내보내기:** 검사 성적서를 `.xlsx`로 받거나, 인쇄 화면(`/app/inspections/:id/print`)에서 "인쇄 / PDF로 저장"으로 A4 PDF를 만듭니다.

#### 기준정보 `/app/items` · `/app/processes` · `/app/plans` · `/app/customer-rules` · `/app/import`

왼쪽 메뉴 "기준정보 및 시스템 관리"의 품번·BOM·라우팅, 공정, 관리계획서, 엑셀 일괄 등록과 「고객 및 협력사」의 클레임 설정(고객사별 8D 기한)을 누르면 이 화면들이 열립니다. 메뉴 항목은 기존과 같은 권한으로 보입니다.

- **품번·BOM·라우팅(`/app/items`, `:id`):** 목록에서 "새 품번"으로 만들고, 기록 페이지에서 속성(품번·품명·구분)과 BOM 표, 라우팅 표를 한 번에 고쳐 `Ctrl+S`(또는 저장 띠의 저장 버튼)로 저장합니다. 엑셀에서 복사한 칸을 붙여 넣을 수 있으며, 자품번·공정처럼 고르는 칸은 화면에 보이는 이름(예: `품번 품명`) 그대로 붙여 넣어야 합니다. 저장은 전부 되거나 하나도 안 됩니다.
- **공정(`/app/processes`)·고객사별 8D 기한(`/app/customer-rules`):** 표의 맨 아래 빈 줄에 입력하면 새 줄이 되고, 저장 띠에서 저장합니다. "엑셀로"로 표 전체를 받습니다.
- **관리계획서(`/app/plans`, `:id`, `:id/print`):** 검사기준서와 같은 방식(목록·미리보기, 표 편집·붙여넣기, 승인 서명, 새 개정, 이전 개정과 비교, 개정 이력, 내보내기)입니다. 승인본에서는 "검사기준 초안 만들기"로 검사 구분이 있는 항목의 검사기준 초안을 만들고 링크로 이동합니다. 인쇄 화면(`/app/plans/:id/print`)은 A4 가로 한 쪽입니다.
- **엑셀 일괄 등록(`/app/import`):** 가져오기 설정을 고르고 `.xlsx`·`.csv` 파일을 올린 뒤 "미리보기"로 등록될 줄과 오류를 확인하고, 오류가 없을 때만 "확정"으로 등록합니다(`N건 등록했습니다.`). 한 줄이라도 틀리면 하나도 등록하지 않습니다.

- **부서·거래처·사용자 정의 칸:** 관리 화면 메뉴 "기준정보 및 시스템 관리"의 부서·사용자 정의 칸, "고객 및 협력사"의 거래처에서 편집합니다. 추가·수정은 품질팀장(과 시스템 관리자)만 할 수 있고 다른 역할은 보기만 합니다. 행은 지우지 않고 "사용"을 끕니다. 거래처 한 곳에 협력사·고객사·외주처·교정기관 구분을 여러 개 고를 수 있고, 거래처에는 코드·이름·구분·상태·등급과 품질 담당자 1명(이름·전화·이메일)만 두고, 인증서는 거래처 화면 안에서 함께 적습니다. 부서는 상위 부서와 부서장으로 조직도를 만듭니다. 더 필요한 칸은 "사용자 정의 칸"에 칸(글·수·날짜·예·아니오·선택·거래처·사용자)을 만들면 그 대상의 관리 화면에 입력 칸이 생깁니다. 저장한 칸의 키와 대상은 바꿀 수 없고, 사용을 꺼도 이미 입력한 값은 남습니다.
- **연결·첨부 탭:** 품번·검사·검사기준서·관리계획서 기록 페이지 오른쪽의 "연결" 탭은 그 기록을 가리키는 기록(부적합·검사·메모 등)과 그 기록이 가리키는 기록을 묶음별로 보여 주고, 볼 권한이 없는 묶음은 숨깁니다. "첨부" 탭에서 사진·사양서·도면·성적서 등 파일을 올리고 받습니다.
- **번호 코드값·번호 규칙:** 품번·문서번호 자동 부여에 쓰는 코드값과 틀은 관리 화면의 "번호 코드값"·"번호 규칙"에서 편집합니다(아래 "새 기능 사용법"의 번호 자동 부여·번호 체계 바꾸는 법 참고). 품번 등록 창의 "자동 번호"가 이 규칙을 씁니다.

#### LOT 이력 `/app/trace` · 미분류 메모 `/app/memos`

- **LOT 이력:** LOT 번호(또는 품번·품명 일부)를 넣으면 상위·하위 계보가 상자와 화살표 그림으로 나오고, 보류 LOT은 빨간 테두리와 `보류` 표시로 구분됩니다. 상자를 누르면 그 LOT으로 옮겨 가고, 아래에 이 LOT에 일어난 일(검사·부적합 등)이 시간순으로 화살표로 이어져 나옵니다.
- **미분류 메모:** 기록을 정하지 않고 적은 메모가 모입니다. 종류(LOT·부적합·CAPA·8D·SCAR·문서·품번)와 번호를 골라 붙이면 그 기록의 메모로 옮겨 가고 목록에서 빠집니다.

#### 기록 화면 `/app/r/<앱>/<모델>/<번호>` (문서·계측기·검사원 자격·LOT·부적합·보류·CAPA·클레임·SCAR·4M 변경)

- 문서·문서 개정·계측기·검사원 자격·LOT·부적합·보류·CAPA·고객 클레임(8D)·고객사별 8D 기한·SCAR·4M 변경은 새 기록 화면으로 열립니다. 검색·위젯·종합현황·메모·승인 후 돌아가기 링크도 이 화면으로 갑니다. 목록은 `/app/r/qms/document`처럼 번호 없이 엽니다(탭·검색·"엑셀로").
- 화면 위에 칸, 아래에 하위 표(문서는 개정 이력), 오른쪽에 관련 기록·메모·첨부·변경 이력 탭이 있습니다. 변경 이력 탭은 그 기록을 볼 권한이 있으면 보입니다.
- 「수정」을 누르면 칸이 입력란으로 바뀌고 「저장」하면 서버가 모델 검증·잠금 규칙대로 저장합니다. 오류는 칸 아래에 보이고, 변경은 변경 이력 탭에 남습니다. 승인자·승인 일시 같은 서명 칸은 이 화면에서 바꿀 수 없고 「승인」(비밀번호 재입력)으로만 채워집니다. 파일 칸(교정 성적서 등)은 첨부 탭이나 「⋯ → 관리 화면에서 열기」를 씁니다.
- 승인 대상(문서 개정)은 품질팀장에게 「승인」 버튼이 보입니다. 승인된 기록은 「수정 요청」(사유·비밀번호) → 시스템 관리자 승인 후 1회만 고칠 수 있고, 삭제는 「⋯ → 삭제 요청」입니다. 다른 사람이 먼저 저장했으면 저장이 거부되니 새로 불러와 다시 고칩니다.
- **부적합**: 품질팀장에게 「처분」 버튼이 보입니다. 처분·특채 고객 승인번호·실패비용을 넣고 MRB 승인 비밀번호를 입력하면 관리 화면과 같은 규칙(재작업·수리 재검사 합격, 특채 승인번호, 폐기·반품 보류 유지)으로 처분되고 종결됩니다. 처분 칸은 「수정」으로 바꿀 수 없습니다. LOT·발견 일시·사진은 관리 화면에서 고칩니다.
- **LOT**: 그 LOT의 부적합·보류가 아래 표에 나오고, 「⋯ → LOT 이력 (추적)」으로 계보 추적 화면을 엽니다. 목록의 「보류 중」 탭은 해제되지 않은 보류가 있는 LOT입니다.
- **보류**: 읽기 전용입니다. 부적합 등록으로 생기고 처분으로만 풀립니다.
- **CAPA·클레임·SCAR 종결**: 「종결」 버튼을 누르면 종결일이 지금으로 들어갑니다. 8D 전 단계, SCAR 협력사 회신, CAPA 유효성 「유효」가 없으면 그 이유가 뜨고 종결되지 않습니다. 종결일은 「수정」으로 바꿀 수 없습니다. CAPA 유효성·담당자·확인자는 관리 화면에서 넣습니다.
- **클레임**: 현재 8D 단계, D3·D5 기한, D1~D8 내용이 순서대로 보이고 D1~D8은 「수정」으로 채웁니다. 「⋯」 메뉴에 LOT 이력 (추적)과 CAPA 만들기가 있습니다(SCAR·부적합도 CAPA 만들기). CAPA 화면의 「출처 기록」은 그 클레임·SCAR·부적합으로 갑니다.
- **4M 변경**: 「초품 합격」 칸에 적용 후 첫 합격 검사가, 승인됐는데 아직 없으면 「미확인 (출하 차단)」이 보입니다. 고객 승인 문서번호는 승인 전에 「수정」으로 넣습니다.

## 사내망 서비스 (팀 공유)

혼자 쓸 때는 위의 `runserver`로 충분합니다. 팀원이 각자 PC에서 접속하게 하려면 아래처럼 띄웁니다(waitress, 무료).

```powershell
powershell -ExecutionPolicy Bypass -File scripts\serve.ps1 -HostName QA-PC01 -ListenIp 192.168.0.10   # QA-PC01 = 이 PC 이름, 192.168.0.10 = 사내망 IP
```

- `-ListenIp`를 빼면 이 PC의 모든 네트워크 연결(외부 Wi-Fi·VPN 포함)에서 접속을 받습니다. 노트북에서 띄울 때는 꼭 사내망 IP를 지정합니다(`ipconfig`로 확인).

- 팀원은 `http://QA-PC01:8000`으로 접속합니다. Windows 방화벽이 묻으면 "개인/도메인 네트워크 허용"을 선택합니다.
- 서명·세션용 비밀키는 처음 실행할 때 `data/secret_key.txt`에 자동으로 만들어집니다(Git에 올라가지 않음). 이 파일을 지우면 모두 다시 로그인해야 합니다.
- 첨부파일(문서 원본)은 로그인한 사용자만 내려받을 수 있습니다.

## 휴대폰에서 사진 찍기

QMS > "부적합 등록"(`/nc/new/`)에서 휴대폰 카메라로 바로 찍어 올릴 수 있습니다. 먼저 **회사 보안 정책(사내망 포트 개방 가능 여부)을 확인**하세요.

1. `QMS_ALLOWED_HOSTS=<PC IP>` 환경변수를 설정합니다.
2. `python manage.py runserver 0.0.0.0:8000`으로 띄웁니다(또는 `scripts\serve.ps1`의 host를 바꿉니다).
3. 관리자 PowerShell에서 방화벽을 엽니다.
   `New-NetFirewallRule -DisplayName QMS -Direction Inbound -LocalPort 8000 -Protocol TCP -Action Allow`
4. 휴대폰(같은 사내망)에서 `http://<PC IP>:8000/nc/new/`로 접속합니다.

## 새 기능 사용법

- **부적합 간편 등록 · 카메라**: `/nc/new/`에서 LOT 번호(바코드 스캔 가능), 발생 유형, 내용, 불량 수량, 사진만 적고 저장합니다. 휴대폰에서는 "사진"을 누르면 카메라가 열리고 여러 장을 올릴 수 있습니다(아이폰 HEIC 가능, 한 장 10MB까지). 저장하면 LOT과 하위 계보가 바로 보류됩니다. 나머지 항목(불량유형·공정·긴급 조치 등)은 부적합 화면에서 보완해야 처분할 수 있습니다.
- **메일 보내기**: 승인(MRB 서명)된 부적합의 "메일 보내기"(`/nc/<번호>/mail/`)에서 제목·본문을 복사해 **아마란스(웹메일)에 붙여넣고**, 사진은 "사진 ZIP"으로 받아 첨부합니다. 보낸 뒤 "보냈음 표시"를 누르면 발송 일시가 남습니다. 아래의 `QMS_SMTP_*` 환경변수를 설정했다면 수신자를 적고 바로 **SMTP로 발송**할 수도 있습니다(실패하면 보냈음 표시는 하지 않습니다).
- **삭제·수정 요청**: 일반 사용자는 기록 화면의 "삭제 요청"에 사유와 본인 비밀번호를 넣어 요청합니다. 요청은 내 할 일에 뜨고 시스템 관리자가 승인해야 삭제됩니다(부적합을 지우면 그 부적합이 만든 보류도 함께 사라지고, 같은 LOT에 걸린 다른 부적합의 보류는 그대로입니다). 이미 승인된(잠긴) 기록은 "수정 요청" → 관리자 승인 후 **1회만** 수정할 수 있습니다(저장이 검증 오류로 실패하면 수정 권한은 남습니다). **시스템 관리자(슈퍼유저)는 요청 없이 바로 수정·삭제**하며, 모든 변경은 이력에 남습니다.
- **통합 검색**: 화면 위 검색창이나 `Ctrl+K`. LOT 번호를 정확히 넣고 Enter(바코드 스캐너 포함)하면 바로 그 LOT의 추적 화면으로 이동합니다. 품번·부적합·8D·문서 등도 찾습니다(권한 있는 것만).
- **LOT 타임라인**: `/trace/`에서 LOT을 열면 공정·검사·부적합·출하·메모가 시간순으로 보입니다.
- **현장 메모**: `/memo/new/`에서 말한 사람(심사원·고객 등)과 내용, 사진을 적습니다. LOT·부적합 등에 연결하면 그 기록 이력에 보이고, 연결 안 한 메모는 미분류함(`/memo/inbox/`)에서 종류+번호로 연결합니다. 심사 날짜에 쓴 메모는 심사에 자동으로 묶입니다. 수정은 작성자만 할 수 있습니다.
- **심사 자료 출력**: `/audit-pack/`에서 품번과 기간을 고르면 검사 요약·부적합·처분·CAPA·메모를 한 장으로 모아 인쇄/PDF로 저장하고, "ZIP"으로 사진·문서 원본을 한 번에 받습니다.
- **연차·급여**: `/me/`는 **본인만** 볼 수 있습니다(시스템 관리자도 남의 것은 못 봄). 같은 DB에 저장되므로 서버 백업에 **포함**되고, 급여 명세서 파일은 `data\private\personal\`에 저장돼 백업에 함께 들어갑니다(웹 주소로는 열리지 않음). 아래 "개인 연차·급여 자료"를 참고하세요.
- **공장 종합현황**: `/overview/`(또는 내 할 일 오른쪽 위 "공장 종합현황")는 DB에 등록된 작업지시·실적·검사·부적합·CAPA·계측기 기록을 생산·품질 카드로 모아 보여줍니다. 설비 실시간 값은 없고, "계획"은 작업지시의 계획 수량입니다. 카드를 누르면 같은 조건으로 걸러진 목록이 열리며, 볼 권한이 없는 카드는 보이지 않습니다.
- **관련 기록**: LOT·작업지시·작업 실적·부적합·보류·출하·검사·고객 클레임·SCAR 화면 아래 "관련 기록" 칸에서 이어진 기록(최대 5건)과 "LOT 이력 조회" 버튼으로 바로 이동합니다. 6건 이상이면 "전체 N건 보기"로 걸러진 목록이 열립니다.
- **번호 자동 부여**: 품번은 새 화면 `/app/items`의 "새 품번"에서 "자동 번호" 스위치를 켜고 규칙(제품코드·원자재·도면 품번·표준품)을 고르면 칸마다 드롭다운이 나오고, 다음 번호를 미리 보여 줍니다. 저장할 때 서버가 번호를 다시 계산해 확정합니다. 미리보기 옆 "직접 고치기"를 누르면 그 번호를 품번 칸에 채워 직접 고칠 수 있습니다. 문서번호는 관리 화면(`/admin/`)의 문서 추가에서 문서번호를 비워 두고 "번호 규칙"을 고릅니다. 규칙을 고르면 `?rule=<id>`가 붙어 화면이 그 규칙의 드롭다운으로 다시 열리므로, 다른 칸을 적기 전에 **번호 규칙부터 고르세요.** 문서 개정의 `개정` 칸을 비우면 마지막 숫자 개정 + 1(첫 개정은 0)로 채웁니다. 긴 번호는 목록·상세에서 마우스를 올리면 자리별 뜻이 보입니다. 직접 입력은 그대로 허용되고 모양 검사는 하지 않습니다.
- **번호 체계 바꾸는 법**: 관리 화면의 "번호 코드값"·"번호 규칙"에서 고칩니다(품질엔지니어·품질팀장). 기존 번호는 다시 매기지 않고, 바꾼 규칙은 새 번호부터 적용됩니다. 저장된 규칙의 이름·대상·틀은 고칠 수 없으므로 새 틀은 규칙을 새로 추가하고 옛 규칙을 "사용 중지"합니다.

  | 바뀌는 것 | 하는 일 | 개발자 필요 |
  | --- | --- | --- |
  | 고객사·산업·자재 등 코드값 추가·이름 변경 | 관리 화면 "번호 코드값"에서 추가·수정 | 아니오 |
  | 코드값 폐지 | "사용 중지" (예전 번호 풀이는 유지) | 아니오 |

- **기존 기록을 거래처·부서에 연결(`link_masters`)**: 거래처·부서·사용자를 등록한 뒤, 예전 기록의 글자 칸(LOT 협력사, 출하·클레임·PPAP·고객사별 8D 기한의 고객사, SCAR 협력사, 내부심사 피심사 부서·심사원)을 새 기준정보에 연결합니다. 글자 칸은 그대로 두고 비어 있는 연결 칸만 채웁니다. 공백·대소문자는 무시하고, 후보가 정확히 1개일 때만 연결합니다(거래처는 코드·이름·영문명, 협력사·고객사 구분이 맞아야 함).

  ```powershell
  .\.venv\Scripts\python manage.py link_masters                                              # 미리보기: 아무것도 바꾸지 않고 연결될 건수와 못 찾음·여러 후보·구분 불일치를 보여 줌
  .\.venv\Scripts\python manage.py link_masters --apply --backup-dir "\\NAS\quality\qms-backup" # 먼저 backup을 실행한 뒤 연결
  ```

  미리보기에서 못 찾은 이름은 거래처·부서를 등록하거나 이름을 맞춘 뒤 다시 실행합니다. `--backup-dir` 대신 환경변수 `QMS_BACKUP_DIR`을 써도 됩니다. 연결 기록은 변경 이력에 "기준정보 연결(link_masters)"로 남습니다.
- **대시보드 편집**: 내 할 일 화면의 "대시보드 편집"에서 위젯을 끌어 빈칸에 놓거나(방향키로 한 칸씩도 가능), 크기(보통 1칸·넓게 2×2칸, 넓게는 세부 목록 표시)를 바꾸고, 추가·삭제한 뒤 "저장"합니다. 사용자별로 저장되며, 지우면 기본 배치로 돌아갑니다. 권한이 없는 위젯은 보이지 않습니다.

## 모듈

- **MES**: 품번·BOM·공정 라우팅, 작업지시·작업 실적(투입·양품·불량, 이전 공정 실적 없으면 등록 차단, 진도율), LOT·계보(분할·병합), 출하
- **CAPA**: 8D·SCAR·부적합·심사 지적 화면의 "CAPA 만들기" → 담당·기한 → 조치 완료 → 유효성 확인("유효")해야 종결
- **내부심사**: 계획·실시·지적(중부적합/경부적합/관찰/개선기회). 중·경부적합은 CAPA가 연결돼야 심사 종결
- **PPAP**: 제출을 만들면 AIAG 18요소가 수준(1~5)에 맞게 생성되고 관리계획서·출하검사가 자동 연결. 제출(S) 요소에 문서·기록이 모두 있어야 PSW 승인 서명 가능, "인쇄/PDF"가 PSW 요소표
- **부적합**: 등록 즉시 LOT과 하위 계보 전체 자동 보류 → 투입·출하 차단. MRB 처분(재작업·수리는 재검사 합격 기록 필요, 특채는 고객 승인번호 필요, 폐기·반품은 보류 유지)
- **검사**: 검사기준(개정·승인 서명, 승인 후 잠금) → 검사 → "저장하고 판정하기" → 불합격이면 부적합 자동 등록
- **고객 클레임(8D)**: 접수 즉시 부적합·보류, 고객사별 D3·D5 기한, D1~D8 모두 채워야 종결
- **SCAR**: 협력사 시정요구, 회신 기한
- **문서**: 원본 파일 + 개정 + 승인 서명, 유효본 = 승인된 최신 개정
- **심사 증적**: 체크리스트 항목에 문서·기록 연결, 미비 항목 표시
- **보고서**: 각 기록 화면의 "출력" → 인쇄/PDF, 또는 등록한 고객 엑셀 양식(셀 매핑)으로 다운로드
- **출하성적서(COA)**: 출하 화면의 "인쇄/PDF"가 성적서가 됩니다(최신 합격 출하검사, 없으면 공정검사). 고객 엑셀 양식은 대상 기록을 "출하"로 하고 매핑에 `{"A10": "coa_rows"}`처럼 표 시작 셀을 적으면 항목·특별특성·LSL·USL·단위·측정값·판정이 아래로 채워집니다
- **재발 방지**: 부적합·클레임 화면에 같은 품번(계보 포함)·같은 불량유형·비슷한 설명의 과거 종결 사례와 그 8D의 D4·D7을 표시
- **검사 입력 화면**: LOT 바코드를 스캔하면 승인된 현재 검사기준이 뜨고, 값을 넣는 즉시 규격 이탈을 빨간색으로 표시. "판정"은 전부 저장되거나(자격·교정·기준 검사 통과) 아무것도 저장되지 않습니다
- **입고 등록·바로가기**: 없는 LOT 번호를 넣으면 그 자리에서 입고 등록(품목은 승인된 검사기준이 있는 것만, 협력사는 기존 입력값 목록)을 하고 바로 검사합니다. LOT 화면에서 기준서·이 품목 지난 성적서·수입검사 관리대장·부적합 관리대장으로 이동하고, 결과 화면에서 성적서를 인쇄합니다. 불합격이면 측정 화면에서 고른 불량유형·불량수량이 자동 등록된 부적합에 들어갑니다. 관리 화면의 "검사 추가"는 이 화면으로 이동합니다(지난 검사 소급 입력은 `/admin/qms/inspection/add/?full=1`)
- **KPI 입력**: 부적합에 불량유형·불량 수량·실패비용, 클레임에 불량 수량, 구매 자재 LOT에 협력사를 적어야 KPI와 협력사 성적표가 채워집니다
- **SPC**: 부분군 n=1이면 I-MR, 2~10이면 X̄-R 관리도, Cpk, 경보(관리한계 이탈, R/MR 이탈, 연속 9점). 특별특성(CC·SC)은 경보 시 부적합 자동 등록·보류, 일반 항목은 내 할 일에 경보 표시
- **계측기**: 교정 대장. 측정값에 계측기를 적으면 교정 기한이 지난 계측기는 거부. 교정 14일 전부터 내 할 일에 표시. 목록의 "남은 일수" 열에 `D-n`·`오늘까지`·`기한 지남 n일`이 보입니다
- **검사원 자격**: 검사구분별 자격·유효기한. 그 검사구분에 자격 기록이 하나라도 생기면 그때부터 자격자만 판정 가능 (자동수집 `collect`은 검사자가 없어 판정되지 않으므로, 자격을 쓰는 검사구분은 자동수집 대신 직접 입력)
- **관리계획서(PFMEA)**: 공정·특성·특별특성·규격·S/O/D·조치우선순위(AP). 승인 후 "검사기준 초안 만들기"로 검사기준 생성
- **4M 변경**: 고객 통보 대상은 고객 승인번호가 있어야 승인. 승인 후 적용 일시부터 그 품번의 합격 검사(초품)가 나올 때까지 출하 차단

### 모듈 켜기/끄기

쓰지 않는 모듈은 시스템 관리자가 `/admin/core/moduleswitch/`(메뉴 「모듈 켜기/끄기」)에서 끕니다. 기록이 없으면 켜져 있는 것입니다.

- 끌 수 있는 모듈: 생산관리(작업지시·실적·출하), 검사, 4M 변경, CAPA, 고객 클레임, 협력사(SCAR), PPAP, 내부심사, 문서 관리, 품질 KPI. 홈·LOT·부적합·보류·기준정보·시스템·개인은 끌 수 없습니다.
- 4M 변경은 검사가, 내부심사는 CAPA가 켜져 있어야 켤 수 있습니다. 거꾸로 이 모듈이 켜져 있으면 검사·CAPA를 끌 수 없습니다.
- 꺼진 모듈의 메뉴는 사라지고, 화면·API는 일반 사용자에게 404입니다. 시스템 관리자는 조회만 할 수 있고 저장은 403입니다. 새 화면(`/app/`)에서는 「비활성 모듈」 안내가 나옵니다.
- 열린 기록(완료 안 된 작업지시, 미판정 검사, 초품 합격 전 4M, 미종결 CAPA·클레임·SCAR·내부심사, 미승인 PPAP)이 있으면 끌 수 없고 번호 목록이 나옵니다.
- 꺼진 뒤에도 시스템 관리자는 CAPA·클레임·SCAR·내부심사를 관리 화면에서 종결하고, 검사 입력으로 판정(4M 초품·재검사)할 수 있습니다.
- 꺼진 모듈의 기록은 내 할 일·기한·알림 메일·위젯·종합현황에서 빠집니다. LOT 이력·검색·관련 기록에는 「비활성 모듈 기록 N건」으로만 나옵니다.
- 꺼진 모듈을 대상으로 한 엑셀 보고서는 404, 엑셀 일괄 등록은 거부됩니다. 검사 모듈이 꺼지면 `collect`는 수집하지 않고 파일을 수신함에 둡니다. 심사 대응 묶음(`/audit-pack/`)에서는 꺼진 모듈 구역이 빠집니다.
- 고객사별 8D 기한은 「고객 및 협력사 › 클레임 설정」에 있고 고객 클레임 모듈에 속합니다.
- 모듈을 꺼도 업무 규칙(LOT 보류 인터록 등)과 기존 기록은 그대로입니다.

## 회사 데이터와 백업

회사 데이터(DB, 첨부파일)는 `data/` 폴더에만 저장되며 Git에 올라가지 않습니다. 위치를 바꾸려면 환경변수 `QMS_DATA_DIR`을 지정합니다.

```powershell
# 수동 백업
.\.venv\Scripts\python manage.py backup "\\NAS\quality\qms-backup"
# 매일 18:00 자동 백업 등록 (Windows 작업 스케줄러)
powershell -ExecutionPolicy Bypass -File scripts\register_backup_task.ps1 -Dest "\\NAS\quality\qms-backup"
```

30일이 지난 백업은 자동으로 지워집니다. 백업에는 DB와 `media/` 외에 `private/`(급여 명세서)와 `attachments/`(기록에 붙인 첨부파일)도 들어갑니다.

백업에는 모든 사람의 연차·급여 기록과 명세서 파일이 들어 있습니다. 자동 백업 등록 스크립트는 백업 폴더를 등록한 계정(과 관리자)만 열 수 있게 잠급니다. 잠그지 못했다는 경고가 나오면(NAS 권한 등) IT팀에 그 폴더를 이 계정 전용으로 설정해 달라고 요청합니다. 수동 백업 폴더도 팀 공유 폴더에 두지 않습니다.

복구는 먼저 리허설로 백업이 쓸 만한지 확인한 뒤 실행합니다. 분기마다 리허설을 한 번 해 두면 "백업은 있는데 복구가 안 되는" 일을 막을 수 있습니다.

```powershell
.\.venv\Scripts\python manage.py restore "\\NAS\quality\qms-backup\qms-20261026-180000"           # 리허설: 무결성 검사 + 건수 확인
.\.venv\Scripts\python manage.py restore "\\NAS\quality\qms-backup\qms-20261026-180000" --apply   # 실제 복원 (서버를 먼저 끄세요)
```

실제 복원 전의 데이터는 `data/pre-restore-날짜/`에 따로 보관됩니다. PostgreSQL을 쓸 때의 백업·복원 방식은 아래 "PostgreSQL" 절을 봅니다.

### 개인 연차·급여 자료

`/me/`의 연차·급여는 본인만 열람합니다(관리자도 다른 사람 것은 볼 수 없음). 다만 같은 DB에 저장되므로 서버 백업에는 포함됩니다. 회사를 옮길 때는 내보낸 뒤 지우세요. 명세서 파일은 `data/private/personal/`에 있습니다(백업 대상 `data/`에 포함, 웹 주소로는 열리지 않음).

## PostgreSQL

환경변수 `QMS_DB_NAME`이 있으면 SQLite 대신 PostgreSQL을 씁니다. 없으면 `data/db.sqlite3`를 씁니다.

| 사용자 환경변수 | 값 | 설명 |
| --- | --- | --- |
| `QMS_DB_NAME` | `qms` | DB 이름. 지우면 SQLite로 돌아갑니다 |
| `QMS_DB_USER` | `qms` | 접속 계정 |
| `QMS_DB_PASSWORD` | | 접속 비밀번호 |
| `QMS_DB_HOST` / `QMS_DB_PORT` | `localhost` / `5432` | 기본값이면 지정하지 않습니다 |
| `QMS_PG_BIN` | `C:\Program Files\PostgreSQL\18\bin` | `pg_dump`·`pg_restore` 폴더. 이 기본 위치면 지정하지 않습니다 |

- PostgreSQL 18은 이 PC에서만 접속하도록(`localhost`) 설치합니다. 접속 드라이버는 `requirements.txt`의 `psycopg[binary]`입니다.
- 백업은 `pg_dump`로 `db.dump` 파일을 만들고, 복원 리허설은 임시 DB(`qms_restore_check`)에 실제로 풀어 건수를 센 뒤 지웁니다. `--apply`는 현재 DB를 `data/pre-restore-날짜/db.dump`로 보관한 뒤 `pg_restore`로 한 번에 복원합니다(중간에 실패하면 현재 DB가 그대로 남음).
- SQLite에서 옮길 때: `PYTHONUTF8=1`을 켠 상태에서 `python manage.py dumpdata --natural-foreign -e contenttypes -e auth.permission -o all.json`로 내보내고, 빈 PostgreSQL DB에 `migrate` → 마이그레이션이 넣은 기본 행 비우기 → `loaddata all.json` → `migrate` 순으로 싣습니다. `PYTHONUTF8=1`이 없으면 파일이 cp949로 저장돼 `loaddata`가 실패합니다. 이미 지운 모델의 권한 참조는 빼고 싣습니다.
- SQLite로 되돌리려면 `QMS_DB_NAME`을 지우고 서버를 다시 켭니다. 전환 뒤 PostgreSQL에 입력한 데이터는 SQLite에 없습니다.
