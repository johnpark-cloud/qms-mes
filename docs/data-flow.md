# 데이터 들여오기·내보내기 (PC ↔ 서버)

사람이 PC의 파일(CSV·엑셀)을 서버에 올리고, 서버의 기록을 파일로 받는 흐름을 정한다. 2026-11-20 코드 기준으로 확인했다. 들여오기 기능을 바꾸면 이 문서도 함께 고친다.

## 1. 원칙

1. **원본은 서버 DB 한 곳이다.** PC 파일은 들여오기 전 원자료이거나 받은 사본이다. 사본을 고쳐 다시 올리는 왕복은 두지 않는다. 기록 수정은 화면 안에서 한다.
2. **사람이 직접 올리고 받는다.** 화면에서 파일을 고르고 「확정」을 누를 때만 저장한다. 폴더 자동 감시, 자동 업로드, PC와의 동기화는 두지 않는다.
3. **표 데이터는 CSV가 표준이다.** 엑셀(.xlsx)도 받는다. CSV 글자 인코딩은 UTF-8(BOM 있어도 됨)을 쓰고, 읽지 못하면 CP949(한국어 엑셀 저장)로 읽는다.
4. **미리보기 → 확정.** 미리보기는 저장 없이 모든 행을 검사해 오류를 행 번호와 함께 보여 준다. 확정은 한 행이라도 틀리면 전체를 되돌린다(전부 또는 없음).
5. **모델 검증과 업무 규칙 함수를 거친다.** 행마다 `full_clean()` → `save()`, 판정·입고처럼 규칙 함수가 있는 기록은 그 함수(`submit_inspection`, `receive_lot` 등)를 부른다. DB에 직접 넣지 않는다(2절).
6. **변경 이력이 남는다.** `save()`를 거치므로 simple-history가 행마다 이력을 쓴다.
7. **원본 파일을 남긴다.** 확정한 파일은 원자료 증거로 보관하고, 누가·언제·어떤 파일로·몇 건을 들였는지 기록한다(3단계에서 만든다, 4절).
8. **권한은 서버에서 확인한다.** 대상 기록의 추가(`add_`)와 변경(`change_`) 권한이 모두 있어야 한다. 기존 행을 덮어쓸 수 있기 때문이다.
9. **꺼진 모듈로는 들여오지 않는다**(MOD-12).
10. **표가 아닌 파일**(PDF, 사진, 도면, 메일)은 데이터가 아니라 기록의 첨부(`Attachment`)로 올린다.

## 2. DB에 직접 넣지 않는 이유

PostgreSQL `COPY`나 pgAdmin으로 CSV를 테이블에 바로 넣으면 아래가 모두 빠진다.

| 빠지는 것 | 결과 |
| --- | --- |
| 인터록(`clean()`): 보류 LOT 출하·실적 차단, 교정 기한 지난 계측기 거부, 검사원 자격, 승인된 검사기준만 | 규칙을 어긴 기록이 들어간다 |
| 변경 이력(simple-history) | 누가 무엇을 바꿨는지 남지 않는다(IATF 기록 관리) |
| 자동 처리: 번호 매기기, 판정, 불합격 → 부적합 등록 → 보류 | 판정 없는 검사, 보류 안 된 불합격 LOT이 생긴다 |
| 코드 → id 변환 | CSV는 품번·거래처 코드를 쓰고 DB는 id를 쓴다 |
| 권한 확인 | 권한 없는 사람의 데이터가 들어간다 |

성능은 문제가 아니다. 수천 행은 ORM으로 충분하다. `COPY`가 의미 있는 규모(수십만 행)는 이 시스템의 업무 기록에 없다.

## 5. CSV 표준

### 공통

- 1행은 열 제목, 2행부터 데이터. 빈 행은 건너뛴다.
- 열 제목은 「새로 만들기」 화면의 칸 이름과 같다. 종류별 빈 양식은 「엑셀 일괄 등록」 화면에서 종류를 고르고 「빈 양식 받기(엑셀)」 또는 「CSV」(UTF-8 BOM)로 받는다. 빈 양식 그대로의 열 제목이면 가져오기 설정 없이 들여온다. 빈 양식의 열은 지우지 않는다(없는 열은 그 행 오류).
- 다른 기록을 가리키는 칸은 id가 아니라 사람이 읽는 키를 쓴다. 품목은 품번, 거래처는 거래처 코드, LOT은 LOT 번호, 작업지시는 작업지시 번호, 계측기는 관리번호, 부서는 부서 코드, 사용자는 로그인 아이디를 쓴다.
- 날짜는 `YYYY-MM-DD`, 일시는 `YYYY-MM-DD HH:MM`. 숫자는 소수점 `.`, 천 단위 쉼표 없이 쓴다.
- 예/아니오 칸은 `예`·`아니오`로 쓴다. `Y`·`N`, `1`·`0`, `O`·`X`, `true`·`false`도 받는다.
- 선택지 칸은 화면에 보이는 이름(예: `원자재`, `설비(Machine)`)으로 쓴다.
- 빈 칸은 값 없음이다.
- **키 열**(아래 표 굵은 칸) 값이 이미 있으면 그 기록을 고치고, 없으면 새로 만든다. 키 열이 없는 종류는 늘 새로 만든다.
- 고칠 때는 기록 화면 수정과 같은 칸만 바뀐다. 그 밖의 열(예: 작업지시의 품목)은 비우거나 지금 값과 같아야 한다. 다르면 그 행은 오류다. 승인된 기록은 화면과 같이 잠겨서 오류다.
- 저장은 기록 화면과 같은 길(`core/rules.py` `save_new`·`save_edit`)이다. 그래서 필수 칸, 보류 인터록, 4M 초품 출하 차단, 잠금, 변경 이력이 화면 입력과 똑같이 걸린다. 한 행이라도 틀리면 파일 전체를 되돌린다.
- 하위 기록(심사 발견사항, 심사 항목, 생산실적)은 부모를 키로 적는다: 심사는 심사명, 체크리스트는 이름, 생산실적은 작업지시 번호와 그 품목 공정 순서의 공정 코드.

### 대상을 바꿀 때 고칠 곳

대상은 `SPECS`의 `create`에서 저절로 만든다. 새 기록 종류를 `create`와 함께 `SPECS`에 넣으면 그대로 대상이 된다. 마이그레이션은 필요 없다(`ImportProfile.target` 선택지가 호출형). 예외만 `core/importer.py` 맨 위 표에 적는다.

| 표 | 쓰임 |
| --- | --- |
| `EXCLUDED` | 들여오지 않는 종류(설정 기록) |
| `EXTRA` | `SPECS` 밖 대상(품목) |
| `LEGACY` | 이미 저장된 설정의 대상 키(`item`, `work_order`). 바꾸면 데이터 마이그레이션이 필요하다 |
| `LOOKUP` | 유일 칸이 없는 모델을 가리킬 때 찾는 칸. 그 밖은 `number`·`code`·`username` 중 첫 유일 칸을 자동으로 쓴다 |
| `MATCH` | 고칠 기록을 찾는 키 열. 그 밖은 첫 유일 칸, 다음은 `unique_together`를 자동으로 쓴다 |
| `RESOLVE` | 특별한 외래키 찾기(생산실적 공정, 코드값 상위 코드) |

대상을 더하면 `core/tests_import_targets.py` `SAMPLES`에 예시 한 행을 더한다. 빠지면 테스트가 실패한다. 외래키 칸에 찾는 방법이 없어도 `problems()` 테스트가 실패한다.

### 측정 원자료

검사 1건 = 같은 파일 안의 같은 (LOT, 검사 구분) 행 묶음. `collect`와 같은 형식에 두 열을 더한다.

| 열 | 내용 |
| --- | --- |
| `lot`* | LOT 번호 |
| `type`* | `INCOMING`/`PROCESS`/`OUTGOING` 또는 수입검사/공정검사/출하검사 |
| `characteristic`* | 검사항목 이름(승인된 현재 검사기준의 항목) |
| `value`* | 계량형은 숫자, 계수형은 `OK`·`1`·`PASS`·`합격`이면 합격, `NG`·`0`·`FAIL`·`불합격`이면 불합격. 그 밖의 글은 오류(폴더 수집 `collect`는 불합격으로 본다) |
| `gauge` | 계측기 관리번호. 비면 검사 입력 화면과 같이 맞는 계측기를 자동으로 고른다 |

화면에서 올리면 올린 사람이 검사원이 되고 `submit_inspection`으로 판정한다. 따라서 자격, 계측기 필수, 교정 기한, 불합격 → 부적합 → 보류가 화면 입력과 똑같이 걸린다. 폴더 수집(`collect`)은 지금 그대로 둔다.

- **화면:** 엑셀 일괄 등록에서 「검사 판정 · 측정 원자료(검사 판정)」를 고른다. 「빈 양식 받기(엑셀)」(검사 구분·쓸 수 있는 계측기 목록과 작성 안내가 붙음) 또는 「CSV」로 위 다섯 열 제목만 있는 양식을 받는다. 미리보기는 판정까지 해 본 뒤 되돌리므로 합격·불합격·부적합 번호를 미리 본다. 검사 입력 권한(`qms.add_inspection`)이 없거나 검사 모듈이 꺼져 있으면 선택지에 나오지 않는다.
- **API:** `GET /api/qms/inspect/upload/`(미리보기 열), `POST /api/qms/inspect/upload/`(`file`, `commit` 0|1 → `count`·`errors`·`rows`), `GET /api/qms/inspect/upload/template/`(빈 양식, `kind=xlsx`면 엑셀). 코드: `qms/rules.py` `upload_measurements`.
- **오류:** 없는 LOT·검사 구분·검사기준·검사항목·계측기, 같은 항목 두 번, 숫자 아닌 계량값, 빠진 항목, 자격·교정 기한·계측기 필수 위반. 묶음 하나라도 틀리면 파일 전체를 저장하지 않는다. 부적합 유형·수량 열은 아직 없어 불합격으로 생긴 부적합은 화면 입력에서 유형을 비운 것과 같다.

## 6. 들여오지 않는 것

| 기록 | 이유 |
| --- | --- |
| 보류 | 부적합 등록으로만 생기고 처분으로만 풀린다 |
| 승인·서명·판정·종결 칸 | 비밀번호 재입력 서명과 판정 경로로만 바뀐다(`SIGN_FIELDS`) |
| 변경 이력 | 시스템이 쓴다 |
| 개인 연차·급여 | 본인만 열람한다 |
| 사용자·권한·모듈 설정, 채번 규칙, 사용자 정의 필드, 가져오기 설정, 엑셀 양식 | 보안·설정이라 화면에서 한 건씩 한다 |
| 부적합 | 지금은 부적합 등록 화면에서만. 들여오려면 `save_quick_nc`를 행마다 불러야 한다 — 필요해지면 따로 정한다 |
| 검사기준·관리계획서 | 개정·승인 흐름이 있는 문서. 항목은 화면 표에 붙여 넣는다 |

## 7. 3단계 구현 순서

한 단계씩 테스트 먼저 쓰고 끝낸다.

1. **대상 일반화.** (완료) `SPECS`의 `create` 칸으로 들여오기 대상을 만든다. 키 열로 고치거나 만들고, 외래키는 5절 키로 찾는다. 완료: 5절 종류 전부 미리보기·확정 테스트, 권한 없는 사용자 403, 꺼진 모듈 거부, 보류 LOT 출하 행 오류.
2. **빈 양식 받기.** (완료) 종류마다 표준 열 제목만 있는 CSV를 화면에서 받는다. 그 양식은 설정 없이 들여온다. 완료: 받은 양식을 채워 올리면 그대로 들어간다.
   - **작성 안내.** (완료) 칸마다 필수 여부·적는 값·예를 모델 정의(칸 종류·선택지·도움말·키 열)에서 만든다(`core/importer.py` `guide`, 측정 원자료는 `qms/rules.py` `UPLOAD_GUIDE`). 화면에 안내 표로 보이고, 엑셀 양식(`GET /api/core/import/template/?target=…&kind=xlsx`)에는 「입력」 시트(필수 열 노란색·열 제목 메모·▼ 목록)와 「작성 안내」 시트로 들어간다. 목록은 숨긴 「목록」 시트에 둔다. 구분·예/아니오는 목록 밖 값을 막고, 품번·거래처 같은 외래키는 새로 만들기 화면과 같은 선택지 앞 500개를 보여 주되 목록 밖 값도 경고만 하고 받는다(500개를 넘거나 방금 만든 기록일 수 있어서). 쿼리 이름이 `format`이 아닌 것은 DRF가 `format`을 응답 형식 지정에 쓰기 때문이다.
3. **측정 원자료 화면 업로드.** (완료) 5절 형식, `submit_inspection` 경유. 완료: 합격·불합격(→ 부적합·보류), 자격 없음, 교정 기한 지남, 없는 검사항목이 화면 입력과 같은 결과.
4. **원본 파일·들여오기 기록.** 확정한 파일을 보관하고 누가·언제·파일·대상·건수를 남긴다. 완료: 기록 목록에서 원본 파일을 받을 수 있다.

## 8. 정한 것·정할 것

- **원본 파일 보관 위치(정함):** 지금은 이 PC에 둔다. 위치는 설정 하나로 두어(④에서 `QMS_IMPORT_DIR`, 기본 `data/imports/`) 나중에 NAS나 통합 서버로 옮길 때 설정만 바꾼다.
- **들여오기 기록 열람(제안, ④에서 확정):** 누가·언제·파일 이름·건수는 민감하지 않다. 원본 파일은 들여온 기록 내용과 아이디를 그대로 담는다. 그래서 그 대상 기록의 열람(`view_`) 권한자와 시스템 관리자만 기록을 보고 원본을 받는다. 기록 목록·첨부와 같은 기준이다. 개인 연차·급여는 들여오지 않으므로 본인만 열람 규칙과 부딪히지 않는다.
