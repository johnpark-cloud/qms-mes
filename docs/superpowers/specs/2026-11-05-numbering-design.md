# 번호 부여 체계 설계 (품번·문서번호)

작성일: 2026-11-05 · 상태: 사용자 검토 대기

## 1. 왜 만드는가

- 부서마다 번호 체계를 따로 쓰고 있어 같은 종류의 기록도 번호 모양이 제각각이다.
- 긴 번호(예: `KEN-PQ-01-01`, `1TDS001-BM001`)는 각 자리가 무슨 뜻인지 외워야 읽을 수 있다.
- 규칙은 앞으로도 바뀐다(고객사·문서종류 추가 등). 규칙이 바뀔 때마다 프로그램을 고치면 안 된다.

목표: 사내 표준 세 자료의 규칙대로 번호를 **드롭다운 선택 → 일련번호 자동**으로 받고, 각 자리에 들어가는 코드값은 사용자가 화면에서 고친다.

## 2. 기준 자료

| 자료 | 다루는 번호 |
| --- | --- |
| KEN-PQ-01 사내표준관리절차서 Rev1 | 관리표준 문서번호, 양식번호, 개정 표기 |
| KEN-GD-02 코드부여지침서 Rev1 | 제품코드 7자리, 원자재 코드 10자리, 기술문서 코드 |
| KEN-PQ-01-01~03 관리대장 | 실제 등록된 문서번호 현황(초기 코드값 확인용) |

사용자 확인 사항:
- 품목분류: 1 제품, 2 완제품, 3 반제품, 4 원자재.
- 개정은 `Rev.0`, `Rev.1` … 로 표기한다.
- 입안 부서 불일치는 무시한다. 번호의 부서 자리는 사용자가 드롭다운에서 고른다.
- LOT 번호 규칙은 없다.

## 3. 목표 · 비목표 · 반목표

목표
- 아래 5가지 번호를 드롭다운으로 받는다.
- 코드값(드롭다운 항목)은 관리 화면에서 추가·이름 변경·사용 중지한다.
- 번호에 마우스를 올리면 각 자리의 뜻을 보여 준다.

비목표 (이번에 하지 않음)
- LOT 번호 규칙: 규칙이 없으므로 지금처럼 직접 입력한다.
- 작업지시·클레임·SCAR·변경점 등 다른 번호: 지금 방식 그대로 둔다.
- 번호 "모양"(자리 순서·자릿수·구분자)을 화면에서 바꾸는 기능: 모양 자체는 표준 개정 때나 바뀌므로 코드로 둔다. 바뀌면 `core/numbering.py` 한 곳만 고친다.
- 기술표준 3자리 일련번호(PQ-01 예외 조항): 실제 사용처가 확인되지 않아 뺀다.

반목표 (이렇게 되면 실패)
- 이미 쓰고 있는 번호가 바뀌거나 지워진다.
- 같은 번호가 두 번 나간다.
- 코드값을 고쳤더니 예전 번호의 뜻을 알 수 없게 된다.
- 직접 입력이 막혀 기존 품번·엑셀 일괄 등록이 안 된다.

## 4. 번호 종류 (모양은 고정, 코드값은 설정)

| # | 종류 | 모양 | 예 | 저장 위치 |
| --- | --- | --- | --- | --- |
| 1 | 관리표준 문서 | `KEN-{문서구분}{부서}-{NN}` | `KEN-PQ-01` | `qms.Document.number` |
| 2 | 양식 | `{상위 관리표준 번호}-{NN}` | `KEN-PQ-01-01` | `qms.Document.number` |
| 3 | 제품·완제품·반제품 품번 | `{품목분류}{산업}{고객사}{NNN}` | `1VDC001` | `core.Item.code` |
| 4 | 원자재 품번 | `{품목분류}{자재}{대}{중}{소}-{NNNNN}` | `41111-00001` (원자재·PBA·Capacitor·Chip·1005) | `core.Item.code` |
| 5 | 기술문서 | `{제품코드 7자리}-{설계자료분류}{NNN}` | `1TDS001-BM001` | `qms.Document.number` |

- 관리표준의 문서구분: M 매뉴얼, P 절차서, F 플로우차트, G 지침서. 부서: A 관리, O 구매자재, D 연구소, P 생산, M 마케팅, Q 품질, S 고객지원.
- 기술문서는 GD-02 파일명 예시(`1TDS001-BM001`)처럼 제품코드 뒤에 `-`를 넣어 읽기 쉽게 저장한다.
- 양식 번호 뒤 `(Rev.0)`은 번호가 아니라 개정 표기다. 번호에는 넣지 않는다.

**[제 판단] 원자재 첫 자리:** GD-02 5.1.2 표는 원자재를 `3`으로 적었지만, 같은 문서 5.1.1과 사용자 확인은 원자재 = `4`다. 첫 자리는 품목분류 코드표의 "원자재" 값을 그대로 쓴다(초기값 `4`). 하위 분류표(GD-02의 `31`, `311` …)는 첫 자리를 뺀 "자재분류 → 대 → 중 → 소" 부모-자식 관계로 저장하므로 첫 자리가 바뀌어도 표는 그대로 맞는다.

**[제 판단] 품목분류 1 제품:** 지금 `Item.item_type`에는 원자재·반제품·완제품만 있다. `제품`(PRD)을 선택지에 추가한다. 선택지 추가만이라 기존 행은 바뀌지 않는다. 품목분류 코드값 ↔ `item_type`은 코드값 행에 `item_type`을 적어 연결한다.

## 5. 코드표 (드롭다운 값)

모델 1개, `core.CodeValue`:

| 필드 | 뜻 |
| --- | --- |
| `group` | 코드 묶음. 고정 선택지: 품목분류, 산업분류, 고객사, 자재분류, 자재 대분류, 자재 중분류, 자재 소분류, 관리표준 문서구분, 부서, 설계자료분류 |
| `code` | 번호에 들어가는 글자(예: `V`, `DC`, `BM`, `1`) |
| `name` | 뜻(예: 전기자동차, 디피코, BOM) |
| `parent` | 자재 대·중·소분류만: 바로 위 분류 값 |
| `item_type` | 품목분류만: 연결되는 `Item.item_type` |
| `active` | 사용 여부. 끄면 드롭다운에서 빠지지만 풀이에는 계속 쓰인다 |
| `sort` | 드롭다운 순서 |

- 같은 `group`·`parent` 안에서 `code`는 중복 불가. 자릿수는 묶음별로 검사한다(산업 1자, 고객사 2자, 설계자료분류 2자, 문서구분·부서 1자, 품목분류·자재 분류들 1자리 숫자).
- 관리 화면(`BaseAdmin`)에서 편집한다. 삭제는 기존 규칙대로 시스템 관리자만 한다. 일반 사용자는 "사용 중지"로 끈다. 변경 이력(simple-history)을 남긴다.
- 권한: 기존 `ensure_roles` 규칙대로 품질엔지니어·품질팀장이 추가·수정 권한을 자동으로 받는다. 검사원은 받지 않는다.
- 초기값: 위 세 자료의 값을 데이터 마이그레이션으로 **추가만** 한다(기존 행 변경·삭제 없음). GD-02의 "0으로 지정" 칸은 `0` = "해당 없음"으로 넣는다.

## 6. 번호 받기

- 일련번호 = 같은 앞자리(prefix)를 가진 기존 번호 중 가장 큰 일련번호 + 1. 지워진 번호를 다시 쓰지 않는다. 직접 입력한 번호도 같은 모양이면 계산에 들어간다.
- 끝 번호(99, 999, 99999)를 넘으면 "일련번호가 다 찼습니다" 오류.
- 번호와 기록 저장은 한 트랜잭션에서 한다. 동시에 같은 번호가 잡히면 기존 unique 제약이 막고, "다시 시도하세요" 오류를 낸다.
- 비활성 코드값으로는 새 번호를 받을 수 없다(서버에서 거부).
- 직접 입력은 그대로 허용한다. 모양 검사는 하지 않는다(기존 번호가 규칙과 다르기 때문).

화면
- **품번(새 화면 `/app` 품번 등록):** 품번 칸 옆 "자동 번호" → 품목분류를 고르면 3번 또는 4번 모양의 드롭다운이 나온다. 자재 대·중·소분류는 앞 선택에 따라 목록이 바뀐다. 다음 번호를 미리 보여 주고, 저장할 때 서버가 다시 계산해 확정한다(미리보기 뒤 다른 사람이 먼저 받았을 수 있으므로).
- **문서번호(관리 화면 문서 추가):** 문서번호를 비워 두고 "번호 종류"(관리표준/양식/기술문서)와 해당 드롭다운을 고르면 저장할 때 번호가 매겨진다. 양식은 상위 관리표준 문서를, 기술문서는 7자리 제품코드 품번을 기존 기록에서 고른다.
- **개정:** 문서 개정의 `개정` 칸을 비우면 그 문서의 마지막 숫자 개정 + 1(첫 개정은 0)로 채운다. 표시는 기존대로 `Rev.n`.

## 7. 긴 번호 읽기

- `describe(number)`: 번호를 5가지 모양에 맞춰 자리별로 나누고 코드표에서 뜻을 찾아 돌려준다. 모양에 안 맞으면 빈 결과.
- 새 화면 품번 목록·상세, 관리 화면 문서 목록에서 번호에 마우스를 올리면 `1 제품 · V 전기자동차 · DC 디피코 · 001` 처럼 보여 준다.
- 사용 중지된 코드도 풀이에는 쓴다. 코드표에 없는 글자는 "미등록"으로 표시한다.

## 8. 바뀌는 곳 (예상)

- `core/models.py`: `CodeValue` 추가, `Item.TYPES`에 `PRD 제품` 추가.
- `core/numbering.py` (새 파일): 번호 계산·풀이.
- `core/migrations/`: 스키마 1개 + 초기 코드값 데이터 1개(추가만).
- `core/admin.py`: `CodeValue` 관리 화면.
- `core/api/`: 드롭다운 목록·다음 번호 미리보기·품번 자동 저장 API, 품번 행에 풀이 추가.
- `qms/admin.py`: 문서 추가 폼의 번호 종류·드롭다운, 개정 자동 채움, 목록 풀이.
- `frontend/src/pages/items/`: 자동 번호 입력, 풀이 표시.
- `README.md`, `docs/business-rules.md`: 번호 규칙 절 추가.

업무 규칙(인터록·판정·승인 등)은 건드리지 않는다. 보안·권한 구조 변경도 없다.

## 9. 구현 세부 결정 [제 판단]

- **상위 연결은 번호 문자열로만:** `Document`에 상위 FK나 종류 컬럼을 추가하지 않는다. 양식의 상위는 번호 앞부분이고, 기술문서의 제품은 앞 7자리다. 양식의 상위 문서 드롭다운에는 1번 모양에 맞는 기존 문서만 보인다. 기술문서의 제품 드롭다운에는 3번 모양에 맞는 기존 품번만 보인다. 스키마 변경과 기존 행 백필이 필요 없다.
- **종류 판별은 모양으로:** 번호 종류는 저장하지 않는다. 모양에 안 맞는 기존 번호는 풀이 없이 그대로 보인다.
- **일련번호 계산은 모양별 정규식으로 엄격하게:** `^{prefix}(\d{N})$`에 정확히 맞는 번호만 센다. 따라서 `KEN-PQ-01-01`은 `KEN-PQ-`의 관리표준 일련번호 계산에 들어가지 않는다.
- **자재 계층:** 품목분류(첫 자리)는 계층 밖에 둔다. 계층은 자재분류(뿌리) → 대분류(부모 = 자재분류 값) → 중분류(부모 = 대분류 값) → 소분류(부모 = 중분류 값) 체인이다. 예: `41111` = 원자재 4 · PBA 1 · Capacitor 1 · Chip 1 · size 1005 1.
- **자릿수 검사:** 세 자료의 초기값은 모두 규칙에 맞는다. 산업은 1자, 고객사 32개는 모두 2자다. 초기 데이터는 건너뛰지 않는다. 데이터 마이그레이션도 같은 검사를 거쳐 넣는다.
- **`PRD 제품`의 영향:** `item_type`으로 분기하는 업무 로직은 `Lot.lineage_gap`(원자재가 아니면 계보 검사)뿐이다. 제품은 완제품과 같이 취급된다. 인터록·판정 규칙은 영향받지 않는다.
- **개정 자동 채움:** 기존 개정값 중 숫자만인 값(앞의 `Rev.`, `Rev`는 떼고 비교)의 최댓값 + 1로 채운다. `A` 같은 문자 개정은 무시한다. 숫자 개정이 없으면 0으로 채운다.

## 10. 빌더에게 맡기는 것

- API 경로 이름, 응답 모양, 화면 배치 세부.
- 관리 화면 문서 폼에서 드롭다운을 바꾸는 방식(폼 필드 + 간단한 스크립트 또는 단계별 저장).
- 초기 코드값의 `sort` 순서(자료에 적힌 순서를 따름).
