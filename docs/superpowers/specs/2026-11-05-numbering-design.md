# 번호 부여 체계 설계 (품번·문서번호)

작성일: 2026-11-05 · 개정: 2026-11-09 (번호 모양을 관리 화면의 "번호 규칙"으로 설정) · 상태: 사용자 검토 대기

## 1. 왜 만드는가

- 부서마다 번호 체계를 따로 쓰고 있어 같은 종류의 기록도 번호 모양이 제각각이다.
- 긴 번호(예: `KEN-PQ-01-01`, `1TDS001-BM001`)는 각 자리가 무슨 뜻인지 외워야 읽을 수 있다.
- 규칙은 앞으로도 바뀐다(고객사·문서종류 추가, 회사 약칭 변경 등). 담당자가 바뀌거나 회사 코드가 바뀌어도 **개발자 없이** 관리 화면에서 고칠 수 있어야 한다(2026-11-06 사용자 결정: 틀 문자열 규칙).

목표: 사내 표준 세 자료의 규칙대로 번호를 **드롭다운 선택 → 일련번호 자동**으로 받는다. 각 자리에 들어가는 코드값과 번호 모양(틀)은 사용자가 관리 화면에서 고친다.

## 2. 기준 자료

| 자료 | 다루는 번호 |
| --- | --- |
| KEN-PQ-01 사내표준관리절차서 Rev1 | 관리표준 문서번호, 양식번호, 개정 표기 |
| KEN-GD-02 코드부여지침서 Rev1 | 제품코드 7자리, 원자재 코드 10자리, 기술문서 코드 |
| KEN-PQ-01-01~03 관리대장 | 실제 등록된 문서번호 현황(초기 코드값 확인용) |
| `BOM(QTMP) 1TRT038_BM001_V01` | 도면 품번·표준품 품번 현장 관행(GD-02 미정의) |

사용자 확인 사항:
- 품목분류: 1 완제품, 2 반제품, 3 원자재 (2026-11-06 사용자 정정. GD-02 표의 '1 제품'은 쓰지 않는다. GD-02 개정은 사용자 몫).
- 개정은 `Rev.0`, `Rev.1` … 로 표기한다.
- 입안 부서 불일치는 무시한다. 번호의 부서 자리는 사용자가 드롭다운에서 고른다.
- LOT 번호 규칙은 없다.

## 3. 목표 · 비목표 · 반목표

목표
- 아래 초기 규칙 7개로 번호를 드롭다운으로 받는다.
- 코드값(드롭다운 항목)은 관리 화면에서 추가·이름 변경·사용 중지한다.
- 번호 모양은 관리 화면의 "번호 규칙"에서 틀 문자열로 정한다. 새 모양은 규칙을 추가하고 옛 규칙을 사용 중지한다.
- 번호에 마우스를 올리면 각 자리의 뜻을 보여 준다.

비목표 (이번에 하지 않음)
- LOT 번호 규칙: 규칙이 없으므로 지금처럼 직접 입력한다.
- 작업지시·클레임·SCAR·변경점 등 다른 번호: 지금 방식 그대로 둔다.
- 조건·계산식이 들어가는 규칙 엔진(예: "고객사가 X면 자릿수 4"). 틀은 고정 글자·코드·기존 번호 참조·일련번호만 잇는다. 담당자가 바뀌어도 읽을 수 있어야 하기 때문이다.
- 새 코드 묶음(예: "공장")을 화면에서 만드는 기능: 묶음 목록은 코드 상수다(1줄 + 마이그레이션).
- 기술표준 3자리 일련번호(PQ-01 예외 조항): 실제 사용처가 확인되지 않아 뺀다.

반목표 (이렇게 되면 실패)
- 이미 쓰고 있는 번호가 바뀌거나 지워진다.
- 같은 번호가 두 번 나간다.
- 코드값이나 규칙을 고쳤더니 예전 번호의 뜻을 알 수 없게 된다.
- 직접 입력이 막혀 기존 품번·엑셀 일괄 등록이 안 된다.

## 4. 번호 규칙 (틀 문자열)

모델 1개, `core.NumberRule`:

| 필드 | 뜻 |
| --- | --- |
| `name` | 규칙 이름(고유). 다른 규칙이 참조할 때 쓴다. 예: 제품코드 |
| `target` | 대상: `ITEM` 품번 / `DOC` 문서 |
| `pattern` | 틀 문자열(아래 문법) |
| `active` | 사용 여부. 끄면 새 번호를 받을 수 없지만 풀이에는 계속 쓰인다 |
| `sort` | 화면 순서, 풀이 때 먼저 맞춰 보는 순서 |

- `name`·`target`·`pattern`은 저장 뒤 바꿀 수 없다. 바꾸려면 새 규칙을 만들고 옛 규칙을 사용 중지한다. 그래야 옛 번호 풀이와 다른 규칙의 참조가 깨지지 않는다.
- 관리 화면(`BaseAdmin`), 변경 이력(simple-history). 삭제는 기존 규칙대로 시스템 관리자만.

### 4.1 틀 문법

중괄호 밖 글자는 그대로 들어가는 고정 글자다.

| 토큰 | 뜻 | 예 |
| --- | --- | --- |
| `{코드 묶음}` | 그 묶음의 활성 코드값 중 하나. 자릿수는 묶음별 고정 | `{고객사}` → `DC` |
| `{코드 묶음:A,B}` | 허용 값을 A, B로 제한 | `{품목분류:1,2}` |
| `{품번:규칙}` / `{문서:규칙}` | 그 규칙 모양에 맞는 기존 품번·문서번호 하나 | `{품번:제품코드}` → `1TRT038` |
| `{품번:규칙:뒤N}` | 고른 번호의 뒤 N글자. N은 토큰 경계에 맞아야 함 | `{품번:제품코드:뒤6}` → `TRT038` |
| `{일련N}` | N자리 일련번호. 정확히 1개, 맨 끝 | `{일련3}` → `001` |

- 코드 묶음 이름은 5절의 묶음 이름 그대로다.
- 부모가 있는 묶음(자재 대·중·소분류)은 바로 앞 코드 토큰의 값의 자식에서 고른다. 바로 앞 코드 토큰이 부모 묶음이 아니면 규칙을 저장할 수 없다.
- 저장 때 검사: 묶음·규칙 이름이 있는지, 허용 값이 코드표에 있는지, 참조 대상(품번/문서)이 참조 규칙의 대상과 맞는지, 자기 참조·순환이 없는지, `뒤N`이 경계에 맞는지, 일련 토큰이 맨 끝에 1개인지.

### 4.2 초기 규칙 7개

데이터 마이그레이션으로 **추가만** 한다.

| sort | 이름 | 대상 | 틀 | 예 |
| --- | --- | --- | --- | --- |
| 1 | 관리표준 | 문서 | `KEN-{관리표준 문서구분}{부서}-{일련2}` | `KEN-PQ-01` |
| 2 | 양식 | 문서 | `{문서:관리표준}-{일련2}` | `KEN-PQ-01-01` |
| 3 | 제품코드 | 품번 | `{품목분류:1,2}{산업분류}{고객사}{일련3}` | `1VDC001` |
| 4 | 원자재 | 품번 | `{품목분류:3}{자재분류}{자재 대분류}{자재 중분류}{자재 소분류}-{일련5}` | `31111-00001` |
| 5 | 기술문서 | 문서 | `{품번:제품코드}-{설계자료분류}{일련3}` | `1TDS001-BM001` |
| 6 | 도면 품번 | 품번 | `{품번:제품코드}-{설계자료분류:AS,SU,DT,PA,BA}{일련3}` | `1TRT038-AS001` |
| 7 | 표준품 | 품번 | `{품목분류:3}{품번:제품코드:뒤6}-{일련4}` | `3TRT038-0001` |

- 관리표준의 문서구분: M 매뉴얼, P 절차서, F 플로우차트, G 지침서. 부서: A 관리, O 구매자재, D 연구소, P 생산, M 마케팅, Q 품질, S 고객지원.
- 기술문서는 GD-02 파일명 예시(`1TDS001-BM001`)처럼 제품코드 뒤에 `-`를 넣는다.
- 양식 번호 뒤 `(Rev.0)`은 번호가 아니라 개정 표기다. 번호에는 넣지 않는다.
- **도면 품번·표준품은 GD-02에 정의가 없다.** 실제 BOM(Pack BOM 721행)의 관행을 반영했다: 기구 부품 약 490건이 도면번호를 품번으로 쓰고(`1TRT038-AS001`, `-DT150`), 구매 완성품 15건이 `3TRT038-0001` 형을 쓴다.
- 도면코드: `AS` 기구 조립도면, `SU` 기구 부분 조립도면, `DT` 기구 상세도면, `PA` 단품도면, `BA` 반제품 보드(GD-02 설계자료분류 중 도면·보드).
- **도면 품번 = 도면 문서번호.** 같은 번호를 품번과 도면 문서가 함께 쓴다. 일련번호는 모든 규칙에서 `Item.code`와 `qms.Document.number` 양쪽을 본다(6절). 백 단위 묶음(AS100번대 등)을 쓰려면 미리보기 번호를 "직접 고치기"로 고쳐 저장한다.
- 표준품의 앞 `3`은 원자재 품목분류다. 뒤 6자리는 기준 제품 품번의 뒤 6자리(산업·고객사·프로젝트 일련번호)다.

**품번 구분(`item_type`) 기본값:** 고른 코드값 중 `item_type`이 적힌 마지막 값의 것을 쓴다. 품목분류(1 ↔ FIN, 2 ↔ SEMI, 3 ↔ RAW)와 설계자료분류 AS·SU·BA ↔ SEMI, DT·PA ↔ RAW에 적어 둔다. 등록 창에서 바꿀 수 있다. `Item.TYPES`는 바꾸지 않는다.

## 5. 코드표 (드롭다운 값)

모델 1개, `core.CodeValue`:

| 필드 | 뜻 |
| --- | --- |
| `group` | 코드 묶음. 고정 선택지: 품목분류, 산업분류, 고객사, 자재분류, 자재 대분류, 자재 중분류, 자재 소분류, 관리표준 문서구분, 부서, 설계자료분류 |
| `code` | 번호에 들어가는 글자(예: `V`, `DC`, `BM`, `1`) |
| `name` | 뜻(예: 전기자동차, 디피코, BOM) |
| `parent` | 자재 대·중·소분류만: 바로 위 분류 값 |
| `item_type` | 품목분류(필수)·설계자료분류(선택)만: 연결되는 `Item.item_type` |
| `active` | 사용 여부. 끄면 드롭다운에서 빠지지만 풀이에는 계속 쓰인다 |
| `sort` | 드롭다운 순서 |

- 같은 `group`·`parent` 안에서 `code`는 중복 불가. 자릿수는 묶음별로 검사한다(산업 1자, 고객사 2자, 설계자료분류 2자, 문서구분·부서 1자, 품목분류·자재 분류들 1자리 숫자).
- 관리 화면(`BaseAdmin`)에서 편집한다. 삭제는 시스템 관리자만. 일반 사용자는 "사용 중지"로 끈다. 변경 이력을 남긴다.
- 권한: 기존 `ensure_roles` 규칙대로 품질엔지니어·품질팀장이 `CodeValue`·`NumberRule` 추가·수정 권한을 자동으로 받는다. 검사원은 받지 않는다.
- 초기값: 위 세 자료의 값을 데이터 마이그레이션으로 **추가만** 한다. GD-02의 "0으로 지정" 칸은 `0` = "해당 없음"으로 넣는다.
- 원자재 첫 자리 `3`은 품목분류다. 하위 분류표는 첫 자리를 뺀 "자재분류 → 대 → 중 → 소" 부모-자식 관계로 저장한다.

## 6. 번호 받기

- 일련번호 = 일련 토큰 앞까지의 글자(prefix)가 같은 기존 번호 중 가장 큰 일련번호 + 1. `Item.code`와 `qms.Document.number` 둘 다에서 `^{prefix}(\d{N})$`에 정확히 맞는 것만 센다. 지워진 번호를 다시 쓰지 않는다. 직접 입력한 번호도 같은 모양이면 계산에 들어간다.
- 끝 번호(99, 999, 99999)를 넘으면 "일련번호가 다 찼습니다" 오류.
- 번호와 기록 저장은 한 트랜잭션에서 한다. 동시에 같은 번호가 잡히면 기존 unique 제약이 막고, "다시 시도하세요" 오류를 낸다.
- 사용 중지된 규칙·코드값으로는 새 번호를 받을 수 없다(서버에서 거부).
- 직접 입력은 그대로 허용한다. 모양 검사는 하지 않는다(기존 번호가 규칙과 다르기 때문).

화면
- **품번(새 화면 `/app` 품번 등록):** 품번 칸 옆 "자동 번호" → 규칙(품번 대상 활성 규칙)을 고르면 그 틀의 토큰마다 드롭다운이 나온다. 부모가 있는 토큰은 앞 선택에 따라 목록이 바뀐다. 참조 토큰은 규칙 모양에 맞는 기존 품번 목록이다. 다음 번호를 미리 보여 주고, 저장할 때 서버가 다시 계산해 확정한다. 미리보기 옆 "직접 고치기"는 자동을 끄고 그 번호를 품번 칸에 채운다.
- **문서번호(관리 화면 문서 추가):** 문서번호를 비워 두고 "번호 규칙"(문서 대상 활성 규칙)을 고르면 화면이 그 규칙의 드롭다운으로 다시 열린다. 저장할 때 번호가 매겨진다.
- **개정:** 문서 개정의 `개정` 칸을 비우면 그 문서의 마지막 숫자 개정 + 1(첫 개정은 0)로 채운다. 표시는 기존대로 `Rev.n`.

## 7. 긴 번호 읽기

- `describe(number)`: 모든 규칙(사용 중지 포함)에 맞춰 보고, 처음 맞는 규칙으로 자리별 뜻을 돌려준다. 대상(품번/문서)이 같은 규칙을 먼저, 그 안에서 `sort` 순. 모양에 안 맞으면 빈 결과.
- 고정 글자는 풀이에 넣지 않는다. 참조 토큰은 참조 규칙으로 펼친다. 참조 안의 일련번호는 `{규칙 이름} 일련번호`로 보인다(예: `038 제품코드 일련번호`).
- 새 화면 품번 목록·상세, 관리 화면 문서 목록에서 번호에 마우스를 올리면 `1 완제품 · V 전기자동차 · DC 디피코 · 001 일련번호` 처럼 보여 준다.
- 사용 중지된 코드도 풀이에는 쓴다. 코드표에 없는 글자는 "미등록"으로 표시한다.

## 8. 번호 체계 바꾸는 법 (담당자 교체 대비)

| 바뀌는 것 | 하는 일 | 개발자 필요 |
| --- | --- | --- |
| 고객사·산업·자재 등 코드값 추가·이름 변경 | 관리 화면 "번호 코드값"에서 추가·수정 | 아니오 |
| 코드값 폐지 | "사용 중지" (예전 번호 풀이는 유지) | 아니오 |
| 회사 약칭(KEN → 다른 이름), 자릿수, 자리 순서, 도면코드 목록 | 새 틀로 규칙을 추가하고 옛 규칙을 사용 중지 | 아니오 |
| 위 규칙을 참조하던 규칙(예: 양식 → 관리표준) | 새 규칙을 참조하는 규칙도 하나 더 추가 | 아니오 |
| 새 번호 종류 | 규칙 추가 | 아니오 |
| 새 코드 묶음(예: "공장") | `CodeValue.GROUPS`에 1줄 추가 + 마이그레이션 | 예 (작음) |

- 기존 번호는 절대 다시 매기지 않는다. 규칙 변경은 새 번호부터 적용된다.
- 예: 회사 약칭이 ABC로 바뀌면 `ABC-{관리표준 문서구분}{부서}-{일련2}` 규칙(이름 예: 관리표준2)을 추가하고 관리표준을 사용 중지한다. ABC 문서의 양식을 받으려면 `{문서:관리표준2}-{일련2}` 규칙도 추가한다. KEN 번호의 풀이는 그대로 나온다.

## 9. 바뀌는 곳 (예상)

- `core/models.py`: `CodeValue`, `NumberRule` 추가. `Item`은 바꾸지 않는다.
- `core/numbering.py` (새 파일): 틀 해석·번호 계산·풀이.
- `core/migrations/`: 스키마 + 초기 코드값·초기 규칙 데이터(추가만).
- `core/admin.py`: `CodeValue`·`NumberRule` 관리 화면.
- `core/api/`: 규칙·드롭다운 목록, 다음 번호 미리보기, 품번 자동 저장 API, 품번 행에 풀이 추가.
- `qms/admin.py`: 문서 추가 폼의 번호 규칙·드롭다운, 개정 자동 채움, 목록 풀이.
- `frontend/src/pages/items/`: 자동 번호 입력, 풀이 표시.
- `README.md`, `docs/business-rules.md`: 번호 규칙 절과 "번호 체계 바꾸는 법" 추가.

업무 규칙(인터록·판정·승인 등)은 건드리지 않는다. 보안·권한 구조 변경도 없다.

## 10. 구현 세부 결정 [제 판단]

- **상위 연결은 번호 문자열로만:** `Document`에 상위 FK나 종류 컬럼을 추가하지 않는다. 참조 토큰의 후보는 참조 규칙 모양에 맞는 기존 번호다. 스키마 변경과 기존 행 백필이 필요 없다.
- **종류 판별은 모양으로:** 어떤 규칙으로 받은 번호인지 저장하지 않는다. 모양에 안 맞는 기존 번호(예: 오타 `1TRT38-DT302`)는 풀이 없이 그대로 보인다.
- **일련번호를 두 표에서 계산:** 도면 품번 = 도면 문서번호 문제를 특례 없이 푼다. 다른 규칙은 prefix가 겹치지 않으므로 영향이 없다.
- **기준 제품 조건:** 참조 토큰 `{품번:제품코드}`는 제품코드 규칙 모양이면 품목분류 1·2 모두 허용한다(이전 설계의 "완제품만"을 넓힘).
- **자재 계층:** 품목분류(첫 자리)는 계층 밖에 둔다. 예: `31111` = 원자재 3 · PBA 1 · Capacitor 1 · Chip 1 · size 1005 1.
- **틀·이름·대상 잠금:** 저장 뒤 바꿀 수 없다. 참조된 규칙을 시스템 관리자가 지우면 그 규칙을 참조하는 규칙은 풀이·번호 받기에서 빠진다(오류로 화면이 깨지지 않음).
- **개정 자동 채움:** 기존 개정값 중 숫자만인 값(앞의 `Rev.`, `Rev`는 떼고 비교)의 최댓값 + 1로 채운다. `A` 같은 문자 개정은 무시한다. 숫자 개정이 없으면 0.
