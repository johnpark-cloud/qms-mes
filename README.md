# QMS+MES (localhost)

품질엔지니어 1인이 어느 회사에서든 다시 세울 수 있는 QMS+MES 틀. 비용 0원(Python, Django, SQLite).

## 처음 설치

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
.\.venv\Scripts\python manage.py migrate
.\.venv\Scripts\python manage.py createsuperuser
```

## 실행

프로젝트 폴더의 **`서버시작.bat`을 더블클릭**하면 DB 갱신(migrate) 후 서버가 켜지고 브라우저가 열립니다. 끌 때는 그 검은 창에서 `Ctrl+C`를 누르거나 창을 닫습니다.

갱신할 DB 구조가 있으면 migrate 전에 자동으로 백업합니다(`QMS_BACKUP_DIR`, 없으면 `%USERPROFILE%\qms-backup`; 30일 지난 백업은 지웁니다). 백업이 실패하면 DB 갱신을 하지 않고 멈춥니다.

터미널에서 직접 켤 때:

```powershell
.\.venv\Scripts\python manage.py runserver
```

http://127.0.0.1:8000/ → **내 할 일** 화면이 열립니다.

왼쪽 메뉴는 업무 영역별 7묶음(통합 업무 홈 · 생산관리 (MES) · 품질관리 (QMS) · 품질보증 및 개선 · 고객 및 공급자 · 분석 및 보고서 · 기준정보 및 시스템 관리)으로 나뉘어 있고, 권한이 있는 항목만 보입니다(설계 근거 `docs/ux-improvement-plan.md`). 묶음 제목을 누르면 접고 펼 수 있고, 펼쳐 둔 상태는 그 PC 브라우저에 기억됩니다. 메뉴 항목은 새 화면(`/app/...`)으로 열립니다. 묶음 제목(통합 업무 홈·분석 및 보고서 제외)을 누르면 그 묶음의 한눈에 보기(`/app/hub/<묶음>`)가 열려 목록을 카드로 모아 봅니다. 카드마다 최근 5건·전체 건수가 나오고, 기한이 지난 미완료 건이 있으면 제목 앞에 빨간 「지연 N」이 먼저 보입니다(누르면 그 목록의 「지연」 탭: CAPA·고객 클레임·SCAR·계측기 교정·내부심사·PPAP 제출·경영검토 조치·작업지시 납기·설비 예방보전, 검사원 자격은 「만료」 탭). 같은 탭이 각 목록 화면에도 있습니다. 「추가」로 그 자리에서 새 기록을 만들며(작은 창), 「전체 보기」나 줄을 누르면 전체 목록·상세로 갑니다. 사용자·모듈 설정·관리자 화면(`/admin/`) 메뉴는 시스템 관리자에게만 보이고, 관리자 화면 첫 화면도 같은 묶음으로 정렬됩니다. 딸린 메뉴(예: 심사 관리 아래 체크리스트·증적·심사 자료 출력, 작업지시 아래 생산실적, 설비·예방보전 아래 보전 이력, 부적합(NCR) 아래 부적합 등록·보류, 계측기 관리 아래 교정 이력·측정시스템 분석(MSA))는 사이드바에 따로 나오지 않고, 상위 메뉴 화면 위 탭으로 오갑니다(`core/nav.py` `SUB`). 상위 메뉴를 볼 권한이 없으면 딸린 메뉴가 사이드바에 그대로 나옵니다. 메뉴별(하위 메뉴·안의 작은 화면 포함) 사용법은 `docs/사용법.docx`, 메뉴 나무와 하나씩 검토하는 순서는 `docs/menu-review.md`에 있습니다.

### 새 화면 `/app/` (React, 시범)

`/app/`은 React로 만든 새 화면입니다. 지금은 **내 할 일**(`/app/todo`), **공장 종합현황**(`/app/overview`), **검사기준서**(`/app/specs`), **검사 입력**(`/app/inspect`), **검사 목록·성적서**(`/app/inspections`), **기준정보**(품번·공정·관리계획서·고객사별 8D 기한·엑셀 일괄 등록), **LOT 이력**(`/app/trace`), **미분류 메모**(`/app/memos`), **감사 추적**(`/app/audit`)을 옮겨 두었고, 기존 `/todo/`·`/overview/`와 관리 화면은 그대로 있습니다. 첫 주소(`/`)는 새 내 할 일(`/app/todo`)로 열리고, 메뉴·검색·관련 기록에 있는 옛 화면 링크(내 할 일·종합현황·검사 입력·엑셀 일괄 등록·LOT 이력·미분류 메모)도 새 화면으로 갑니다. 옛 화면은 위쪽 「기존 화면」 링크나 주소를 직접 넣으면 열립니다. 로그인은 기존과 같은 계정을 쓰며, 카드나 줄을 누르면 기존 화면으로 이동합니다. 설계와 단계는 `docs/architecture-migration-plan.md`에 있습니다.

운영 PC에서는 아무것도 더 할 일이 없습니다. 빌드된 파일(`frontend/dist/`)이 저장소에 들어 있어서 `서버시작.bat`이나 `scripts\serve.ps1`로 켜면 그대로 열립니다. **운영 PC에서는 Node.js도 빌드도 필요 없습니다.**

화면을 고치는 개발 PC에서만 Node.js가 필요합니다.

```powershell
cd frontend
npm ci            # 처음 한 번 (패키지 설치)
npm run dev       # 개발 서버: http://localhost:5173/app/ (Django는 127.0.0.1:8000에서 따로 켜 둡니다)
npm run build     # 결과를 frontend\dist\에 만듭니다. 화면을 고쳤으면 이 폴더도 함께 커밋합니다
```

개발 서버 주소는 `127.0.0.1`이 아니라 `localhost`로 엽니다.

#### 검사기준서 `/app/specs`

- **목록:** 품번·검사 구분·상태로 거르고 "엑셀 받기" 링크로 목록을 `.xlsx`로 받습니다. "새 기준서"는 품번과 검사 구분을 골라 Rev.1 초안을 만듭니다(품번·구분은 만들 때만 고릅니다).
- **기록 페이지(`/app/specs/:id`):** 검사항목을 표에서 고칩니다. 엑셀에서 복사한 칸을 붙여 넣을 수 있고(천 단위 쉼표·공백은 정리, 빈 칸은 규격 없음), `Ctrl+S`로 저장합니다. 저장은 전부 되거나 하나도 안 됩니다. 오류는 그 칸에 표시됩니다. 다른 사람이 먼저 고쳤으면 `다른 사람이 먼저 고쳤습니다. 다시 불러오세요.`가 나옵니다.
- **저장 전 변경이 있으면** "승인 서명"과 "이력 남기기"는 눌러지지 않습니다. 먼저 저장하세요.
- **승인:** "승인 서명"은 품질팀장이 비밀번호를 다시 입력해 승인합니다. 승인된 기준서는 읽기 전용이며 "새 개정"으로 다음 개정 초안을 만듭니다(항목 복사). "이전 개정과 비교"는 바뀐 항목을 색으로 보여 줍니다.
- **개정 이력:** "이력 남기기"로 변경 내용과 사유를 신청하면 "대기"이고, 품질팀장이 비밀번호로 확정하면 더는 고칠 수 없습니다.
- **삭제 버튼:** 표의 줄 삭제 버튼은 품질엔지니어·품질팀장에게는 보이지 않습니다(두 역할에 `delete_characteristic` 권한이 없습니다).
- **샘플링:** 샘플링 칸은 목록(예: 전수검사, n=5, AQL)에서 고르고, 목록에 없을 때만 직접 입력합니다.
- **계측기 종류:** 항목마다 "계측기 종류"(예: 마이크로미터, 버니어캘리퍼스)를 적으면 검사 입력 때 그 말이 종류·이름에 들어간, 교정 기한 안의 사용 중인 계측기가 자동으로 골라집니다. 비워 두면 연결된 관리계획서 항목의 측정방법을 씁니다. 새 개정에도 복사됩니다.
- **메모 탭:** 검사기준서에는 메모를 직접 붙일 수 없어서 미분류 메모(`/app/memos`)로 연결됩니다.
- **내보내기·PDF:** "내보내기"는 문서를 `.xlsx`(A4 한 시트)로 받습니다. "PDF"는 인쇄 화면(`/app/specs/:id/print`)을 열고, 브라우저의 "인쇄 / PDF로 저장"으로 만듭니다. 승인 전 문서에는 `초안 — 승인 전` 표시가 들어갑니다.
- **Ctrl+K:** 어느 화면에서나 명령창이 열려 기록을 찾아 이동합니다(결과가 없으면 이동하지 않습니다). 위쪽 「전체 메뉴」로 바꾸면 묶음 → 메뉴 → 최근 기록 8건을 세 칸(파일 탐색기 열 보기)으로 한번에 보며, 칸 위에 마우스를 올리거나 누르면 오른쪽이 바뀌고 글자를 넣으면 메뉴 이름으로 거릅니다.

#### 검사 입력 `/app/inspect`

- **스캔:** LOT 번호를 스캔하거나 입력하고 Enter를 누르면 그 LOT에 맞는 검사 버튼(수입·공정·출하)이 나옵니다. 아래 표는 아직 검사하지 않은 LOT(검사 대기)입니다.
- **LOT 찾기:** 번호를 모르면 번호·품번·품명·공급자 일부를 입력합니다. 맞는 LOT이 목록으로 나오고(보류 LOT은 `보류` 표시), 고르면 바로 조회됩니다.
- **없는 LOT:** 등록되지 않은 번호면 "입고 등록" 창이 열립니다. 품목과 입고수량을 넣고 저장하면 바로 수입검사를 시작할 수 있습니다.
- **측정(`/app/inspect/:lot/:spec`):** 승인된 현재 검사기준의 항목이 표로 나옵니다. 계측기를 고르고 값을 넣으면 즉시 `합격`/`규격 이탈`이 표시되고, Enter로 다음 칸으로 갑니다. "판정"은 기존 화면과 같은 규칙(검사원 자격·계측기 교정 기한·승인된 기준)으로 전부 저장되거나 하나도 저장되지 않습니다. 두 번 눌러도 1건만 저장됩니다. 불합격이면 부적합 번호가 표시되고 LOT이 보류됩니다. 즉시 확인이 끝나기 전에 판정을 눌렀는데 불합격 항목이 있으면, 저장하지 않고 부적합 유형 칸을 먼저 보여 줍니다. 이미 판정한 LOT은 처분 전 부적합이 있을 때(재작업·수리 후 재검사)만 열리고, 이때 경고가 나오며 판정 때 "재검사로 판정할까요?"를 한 번 더 묻습니다. 보류 중인 LOT이면 "합격해도 보류는 부적합 처분 때 풀립니다" 경고가 나옵니다. 계량형 항목의 계측기는 검사기준서의 계측기 종류(없으면 관리계획서 측정방법)에 맞는 교정 기한 안의 계측기로 미리 골라지고(번호순 첫 번째), 맞는 계측기가 없으면 "<종류> 없음(교정 기한 확인)"으로 비어 있습니다. 위의 기본 계측기는 골라지지 않은 계량형 항목에 쓰이고, 표의 "계측기" 열에서 항목마다 다른 계측기를 고를 수 있습니다. 계측기를 하나라도 등록했으면 계량형 항목마다 계측기가 정해져야 판정되며, 빠진 항목은 이름으로 알려 줍니다. 최신 승인 개정이 아니거나 품번이 다른 기준으로는 화면이 열리지 않습니다.
- 기존 `/inspect/` 화면도 그대로 있습니다.

#### 검사 목록·성적서 `/app/inspections`

- **목록:** 수입·공정·출하 탭(`?tab=INCOMING|PROCESS|OUTGOING`)과 검색으로 거르고 "엑셀 받기"로 `.xlsx`를 받습니다. 판정·검사자·검사 일시(기간)로 더 거르고, 열 머리(검사 일시·LOT·품번·공급자·검사기준·검사자·판정)를 눌러 정렬합니다. "엑셀 받기"도 지금 거른 조건·정렬 그대로 받습니다. 판정은 합격·불합격·미판정으로 표시됩니다. 위쪽 요약에 지금 탭·검색 기준의 전체·합격·불합격 건수와 합격률(판정된 검사만 분모)이 나옵니다. 「부적합 등록」은 지금 탭(수입·공정·출하)을 발생 구분으로 채운 부적합 등록 화면을 엽니다(수입 탭이면 공급자 칸이 나옵니다). 줄을 누르면 오른쪽 미리보기에 LOT·판정, 「검사 정보」 표(품번·품명, 공급자, LOT 수량, 검사기준 개정, 샘플링, 검사자, 검사 일시, 부적합, CAPA), 「측정 결과」 표(항목·규격·측정값·OK/NG, 불합격 줄은 빨간 바탕)가 나옵니다.
- **기록 페이지(`/app/inspections/:id`):** 검사 결과와 측정값을 읽기 전용으로 봅니다(판정 후에는 고칠 수 없습니다). 오른쪽 메모 칸에서 이 검사에 메모·사진을 바로 남깁니다(품번 기록 페이지도 같습니다).
- **내보내기:** 검사 성적서를 `.xlsx`로 받거나, 인쇄 화면(`/app/inspections/:id/print`)에서 "인쇄 / PDF로 저장"으로 A4 PDF를 만듭니다.

#### 기준정보 `/app/items` · `/app/processes` · `/app/plans` · `/app/customer-rules` · `/app/import`

왼쪽 메뉴 "기준정보 및 시스템 관리"의 품목·BOM·라우팅, 공정, 관리계획서, 엑셀 일괄 등록과 「고객 및 공급자」의 고객사별 8D 기한을 누르면 이 화면들이 열립니다. 메뉴 항목은 기존과 같은 권한으로 보입니다.

- **프로젝트(`/app/r/core/project`, 메뉴 "고객 및 공급자"):** 고객사(고객 구분 거래처) 아래 차종·프로그램 단위로 프로젝트를 둡니다(코드 비우면 PJ0001처럼 자동, 기간·진행 상태 계획/개발/양산/종료). 품목마다 프로젝트 하나를 고르고(비워도 됨), 프로젝트 화면 아래 그 품목 표가, 거래처 화면 아래 프로젝트 표가 보입니다. 품목·검사기준서·관리계획서 목록에 「프로젝트」 열과 거르기(「프로젝트 없음」 포함)가 있어 제품별 공정·검사기준·관리계획을 프로젝트로 모아 봅니다. 프로젝트가 붙은 품목이 있으면 그 프로젝트는 지울 수 없습니다(사용을 끕니다).
- **품목·BOM·라우팅(`/app/items`, `:id`):** 목록에서 "새 품번"으로 만들고(프로젝트도 고름), 기록 페이지에서 속성(품번·품명·구분·프로젝트)과 BOM 표, 라우팅 표를 한 번에 고쳐 `Ctrl+S`(또는 저장 띠의 저장 버튼)로 저장합니다. 엑셀에서 복사한 칸을 붙여 넣을 수 있으며, 자품번·공정처럼 고르는 칸은 화면에 보이는 이름(예: `품번 품명`) 그대로 붙여 넣어야 합니다. 저장은 전부 되거나 하나도 안 됩니다.
- **공정(`/app/processes`)·고객사별 8D 기한(`/app/customer-rules`):** 표의 맨 아래 빈 줄에 입력하면 새 줄이 되고, 저장 띠에서 저장합니다. "엑셀 받기"로 표 전체를 받습니다.
- **관리계획서(`/app/plans`, `:id`, `:id/print`):** 검사기준서와 같은 방식(목록·미리보기, 표 편집·붙여넣기, 승인 서명, 새 개정, 이전 개정과 비교, 개정 이력, 내보내기)입니다. 승인본에서는 "검사기준 초안 만들기"로 검사 구분이 있는 항목의 검사기준 초안을 만들고 링크로 이동합니다. 인쇄 화면(`/app/plans/:id/print`)은 A4 가로 한 쪽입니다. 한 줄이 PFMEA 한 줄이라 표에 고장 영향·고장 원인·예방 관리·권고 조치 칸이 있고(검출 관리는 측정방법), 「⋯ → PFMEA 엑셀 받기·PFMEA 인쇄/PDF」(`/app/plans/:id/print?kind=pfmea`)로 고장모드가 있는 줄만 PFMEA 양식으로 냅니다. S·O·D는 1~10만 받습니다. 저장된 내용에 아래가 있으면 표 위에 「PFMEA·관리계획서 확인」 경고가 뜹니다(저장·승인은 막지 않음): AP H인데 권고 조치 없음, 심각도 9 이상인데 특별특성 없음, 특별특성인데 고장모드·S·O·D 빈칸, 고장모드가 있는데 측정방법·검사 구분 없음.
- **엑셀 일괄 등록(`/app/import`):** 종류를 고르면 화면에 「작성 안내」 표(열 제목·필수·적는 값·예)가 나오고, 「빈 양식 받기(엑셀)」로 같은 안내가 붙은 엑셀 양식을 받습니다. 엑셀 양식은 필수 열이 노란색이고, 열 제목에 마우스를 올리면 적을 값이 보이며, 구분·예/아니오·품번·거래처처럼 고르는 칸은 ▼ 목록에서 고릅니다. 표준 열 제목만 있는 CSV도 받을 수 있습니다. 어느 양식이든 채워 올리면 가져오기 설정 없이 들어갑니다. 회사 고유 양식은 가져오기 설정을 고르고 `.xlsx`·`.csv` 파일을 올린 뒤 "미리보기"로 등록될 줄과 오류를 확인하고, 오류가 없을 때만 "확정"으로 등록합니다(`N건 등록했습니다.`). 한 줄이라도 틀리면 하나도 등록하지 않습니다. 확정한 파일은 올린 그대로 보관되고, 화면 아래 「들여오기 기록」 표에 일시·올린 사람·종류·파일 이름·건수가 남으며 파일 이름을 눌러 원본을 받습니다(그 기록을 볼 권한이 있는 사람만 보이고, 지우지 않고 영구 보관). 「검사 판정 · 측정 원자료(검사 판정)」를 고르면 LOT·검사 구분·검사항목·값·계측기 열의 측정값 파일을 올려 검사 입력 화면과 똑같이 판정합니다(올린 사람이 검사원, 자격·교정 기한·불합격 → 부적합·LOT 보류가 그대로 걸림). 대상은 문서·계측기·교정 이력·측정시스템 분석(MSA)·검사원 자격·LOT·CAPA·고객 클레임·SCAR·4M 변경·심사·체크리스트·PPAP·품목·작업지시·생산실적·출하·설비·보전 이력·거래처·프로젝트·부서·채번 코드값입니다. 키 열(품번·번호 등)이 이미 있으면 화면 수정과 같은 칸만 고치고, 승인된 기록·보류 LOT은 화면과 똑같이 거부합니다. PC 파일을 들여오고 내보내는 원칙·CSV 표준 열·앞으로 늘릴 대상은 `docs/data-flow.md`에 있습니다.

- **부서·거래처·사용자 정의 필드:** 메뉴 "기준정보 및 시스템 관리"의 부서·사용자 정의 필드, "고객 및 공급자"의 거래처가 새 기록 화면으로 열리고 이름·구분·담당자 같은 칸을 「수정」으로 고칩니다. 부서·거래처는 목록의 「새로 만들기」로 기록 화면에서 등록합니다(부서는 코드·상위 부서·부서장 포함). 거래처 코드는 비워 두면 P0001처럼 다음 번호가 자동으로 붙습니다. 사용자 정의 필드도 목록의 「새로 만들기」로 등록하고, "선택" 종류의 선택지는 칸에 입력하고 Enter(쉼표로 여러 개)로 넣으며 등록한 뒤에도 「수정」으로 더하고 뺍니다. 코드처럼 등록한 뒤 바꾸지 않는 칸은 관리 화면에서 고칩니다. 추가·수정은 품질팀장(과 시스템 관리자)만 할 수 있고 다른 역할은 보기만 합니다. 행은 지우지 않고 "사용"을 끕니다. 거래처 한 곳에 공급자·고객사·외주처·교정기관 구분을 여러 개 고를 수 있고, 구분 네 칸은 "구분" 한 칸에 체크 상자로 모여 있습니다. 거래처에는 코드·이름·구분·상태·등급과 담당자 여러 명(업무·이름·전화·이메일을 한 줄에, 「+ 담당자 추가」·「빼기」)을 두고, 인증서는 거래처 화면 안에서 함께 적습니다. 부서는 상위 부서와 부서장으로 조직도를 만듭니다. 더 필요한 칸은 "사용자 정의 필드"에 칸(글·수·날짜·예·아니오·선택·거래처·사용자)을 만들면 그 대상의 관리 화면에 입력 칸이 생깁니다(새 기록 화면에는 아직 나오지 않습니다). 저장한 칸의 키와 대상은 바꿀 수 없고, 사용을 꺼도 이미 입력한 값은 남습니다.
- **연결·첨부 탭:** 품번·검사·검사기준서·관리계획서 기록 페이지 오른쪽의 "연결" 탭은 그 기록을 가리키는 기록(부적합·검사·메모 등)과 그 기록이 가리키는 기록을 묶음별로 보여 주고, 볼 권한이 없는 묶음은 숨깁니다. "첨부" 탭에서 사진·사양서·도면·성적서 등 파일을 올리고 받습니다. 올린 사람(과 시스템 관리자)은 「지우기」로 파일을 지울 수 있고, 승인된 기록의 첨부는 지울 수 없습니다. 지운 파일 이름·지운 사람·시각은 변경 이력에 남습니다.
- **채번 코드값·채번 규칙:** 품번·문서번호 자동 부여에 쓰는 코드값과 틀은 메뉴 "채번 코드값"·"채번 규칙"(새 기록 화면)에서 이름·틀·순서·사용을 고치고, 목록의 「새로 만들기」로 등록합니다(아래 "새 기능 사용법"의 번호 자동 부여·번호 체계 바꾸는 법 참고). 품번 등록 창의 "자동 번호"가 이 규칙을 씁니다.

#### LOT 이력 `/app/trace` · 미분류 메모 `/app/memos`

- **LOT 이력:** LOT 번호(또는 품번·품명 일부)를 넣으면 상위·하위 계보가 상자와 화살표 그림으로 나오고, 보류 LOT은 빨간 테두리와 `보류` 표시로 구분됩니다. 상자를 누르면 그 LOT으로 옮겨 가고, 아래에 이 LOT에 일어난 일(검사·부적합 등)이 시간순으로 화살표로 이어져 나옵니다.
- **미분류 메모:** 기록을 정하지 않고 적은 메모가 모입니다. 종류(LOT·부적합·CAPA·8D·SCAR·문서·품번)와 번호를 골라 붙이면 그 기록의 메모로 옮겨 가고 목록에서 빠집니다.

- 칸은 구역 카드(예: 부적합은 발생·불량 내용·봉쇄·고객 통보·처분·승인)에 「이름 | 값」 줄로 보이고, 빈 칸은 「빈 항목 N개 보기」로 접힙니다. 유효기한·다음 교정일·납기 같은 기한 칸 옆에는 「D-n」·「n일 지남」 꼬리표가 붙습니다(종결·사용 중지·완료 기록은 없음). 처분·승인·열람 확인을 기다리는 기록은 제목 아래 「다음 행동」 띠에 할 일과 버튼이 먼저 보입니다.
- 화면 위에 칸, 아래에 하위 표(문서는 개정 이력), 오른쪽에 관련 기록·메모·첨부·변경 이력 탭이 있습니다. 변경 이력 탭은 그 기록을 볼 권한이 있으면 보이고, 그 기록에 붙인 첨부(추가·삭제)와 메모(추가·변경) 줄도 함께 나옵니다(첨부·메모 보기 권한이 있을 때).
- 「수정」을 누르면 칸이 입력란으로 바뀌고 「저장」하면 서버가 모델 검증·잠금 규칙대로 저장합니다. 오류는 칸 아래에 보이고, 변경은 변경 이력 탭에 남습니다. 승인자·승인 일시 같은 서명 칸은 이 화면에서 바꿀 수 없고 「승인」(비밀번호 재입력)으로만 채워집니다. 다른 기록을 고르는 칸(거래처·담당자·공정 등)은 선택 목록(500개까지)으로 고르고, ×로 지우면 빈 값으로 저장합니다. 일시 칸은 날짜·시각 입력으로 고칩니다. 자동 번호, 기록이 붙어 있는 부모(문서·심사·PPAP·작업지시), 품번·코드처럼 기록의 정체를 바꾸는 칸, 부적합의 LOT·발견 일시·처분 칸, 실적·출하의 LOT은 바꿀 수 없습니다. 파일 칸(교정 성적서 등)은 첨부 탭을 씁니다. 엑셀 보고서 양식·가져오기 설정·문서 개정도 목록의 「새로 만들기」로 새 화면에서 만듭니다(관리 화면 추가 폼으로 가지 않음): 원본 파일은 「파일 고르기」로 올리고, 셀·열 매핑은 칸 아래 예처럼 JSON으로 적습니다(틀리면 칸 아래 오류). 아래 하위 표(교정 이력·심사 발견사항 등) 제목 옆 「추가」는 부모를 채운 새로 만들기 화면을 엽니다(그 기록에 새로 만들기 칸이 있고 추가 권한이 있으며 부모가 잠기지 않았을 때만). 「⋯ → 관리 화면에서 열기」는 시스템 관리자에게만 보입니다.
- 승인 대상(문서 개정)은 품질팀장에게 「승인」 버튼이 보입니다. 승인된 기록은 「수정 요청」(사유·비밀번호) → 시스템 관리자 승인 후 1회만 고칠 수 있고, 삭제는 「⋯ → 삭제 요청」(같은 화면 안 창에서 사유·비밀번호, 시스템 관리자는 「삭제」)입니다. 다른 사람이 먼저 저장했으면 저장이 거부되니 새로 불러와 다시 고칩니다.
- 문서 개정은 앱 안에서 본문을 씁니다. 「새로 만들기」에서 원본 파일이나 본문 중 하나는 있어야 하고, 둘 다 비우면 직전 개정의 본문을 복사해 시작합니다(그다음 「수정」으로 고침). 개정 화면 「본문」 구역은 줄바꿈 그대로 보이고, 「수정」하면 큰 입력 칸이 됩니다. 직전 개정이 있으면 「이전 개정과 비교」로 더해진 줄(초록)·지워진 줄(빨강 취소선)을 봅니다. 승인된 개정의 본문은 잠깁니다(고치려면 수정 요청 또는 새 개정). 「양식지 · 인쇄」는 문서 정보·본문·개정 이력(이 개정까지의 개정 내용·요청자·승인자·승인일) 한 장입니다. 본문은 서식 없는 글자만 됩니다.
- 승인된 문서 개정에는 「읽었음 (열람 확인)」 버튼이 보입니다(그 문서를 볼 권한이 있는 사람). 누르면 본인 이름·일시가 아래 「열람 확인」 표에 남고 버튼은 사라집니다(두 번 눌러도 한 줄). 승인 전 초안은 열람 확인할 수 없습니다. 최근 30일 안에 승인된 최신 개정 중 내가 아직 읽지 않은 것은 내 할 일 「문서 열람 확인」에 뜹니다(새 개정이 승인되면 옛 개정은 빠짐). 알림 메일에는 넣지 않습니다(사람마다 다름).
- **부적합**: 품질팀장에게 「처분」 버튼이 보입니다. 처분·특채 고객 승인번호·실패비용을 넣고 MRB 승인 비밀번호를 입력하면 관리 화면과 같은 규칙(재작업·수리 재검사 합격, 특채 승인번호, 폐기·반품 보류 유지)으로 처분되고 종결됩니다. 처분 칸은 「수정」으로 바꿀 수 없습니다. LOT·발견 일시·사진은 관리 화면에서 고칩니다.
- **LOT**: 그 LOT의 부적합·보류가 아래 표에 나오고, 「⋯ → LOT 이력 (추적)」으로 계보 추적 화면을 엽니다. 목록의 「보류 중」 탭은 해제되지 않은 보류가 있는 LOT입니다.
- **보류**: 읽기 전용입니다. 부적합 등록으로 생기고 처분으로만 풀립니다.
- **CAPA·클레임·SCAR 종결**: 「종결」 버튼을 누르면 종결일이 지금으로 들어갑니다. 8D 전 단계, SCAR 공급자 회신, CAPA 유효성 「유효」가 없으면 그 이유가 뜨고 종결되지 않습니다. 종결일은 「수정」으로 바꿀 수 없습니다. CAPA 유효성·담당자·확인자는 관리 화면에서 넣습니다.
- **클레임**: 현재 8D 단계, 지연, D3·D4·D5·D8 기한, 「단계별 기한」(단계마다 기한·완료 일시·늦음/지연 중), D1~D8 내용이 순서대로 보이고 D1~D8은 「수정」으로 채웁니다. 「⋯」 메뉴에 LOT 이력 (추적)과 CAPA 만들기가 있습니다(SCAR·부적합도 CAPA 만들기). CAPA 화면의 「출처 기록」은 그 클레임·SCAR·부적합으로 갑니다.
- **4M 변경**: 「진행 단계」(작성 중·검토 중·보류·반려)와 「고객 승인 상태」(해당 없음·요청 전·승인 요청·고객 승인·고객 반려)를 「수정」의 드롭다운으로 고르고, 검토자·검토일·검토 의견을 적습니다. 「승인 완료」는 드롭다운에 없고 승인 서명을 하면 저절로 바뀝니다. 보류·반려·고객 반려 상태에서는 승인 서명이 거부되고, 「고객 승인」을 고르면 고객 승인 문서번호가 있어야 합니다. 고객 통보가 아니면 고객 승인 상태는 「해당 없음」이 됩니다. 목록은 진행 중·보류·반려·승인됨 탭으로 나뉘고, 보류·반려 건은 내 할 일 「승인 대기」에서 빠집니다. 양식지 끝에는 「개정 이력」 표(신규·Rev.1…, 일시·변경자·바뀐 칸 옛 값 → 새 값)가 붙습니다. 「초품 합격」 칸에 적용 후 첫 합격 검사가, 승인됐는데 아직 없으면 「미확인 (출하 차단)」이 보입니다. 고객 승인 문서번호는 승인 전에 「수정」으로 넣습니다.
- **심사**: 발견사항이 표로 보이고 행을 누르면 발견사항 화면으로 갑니다. 「종결」은 실시일이 없거나 CAPA 없는 중·경부적합 발견사항이 있으면 그 이유가 뜨고 종결되지 않습니다. 지적 화면 「⋯ → CAPA 만들기」로 만든 CAPA는 그 지적에 자동으로 연결되어 「CAPA」 칸에 링크로 보입니다.
- **작업지시·실적·출하**: 작업지시 화면 아래에 생산실적(공정 순)과 LOT이 표로 보입니다. 기록 화면에서는 계획 수량·납기·상태, 실적의 투입·양품·불량 수량, 출하의 고객·수량만 고칩니다(양품+불량은 투입보다 많을 수 없음). 새 작업지시·실적·출하는 목록의 「새로 만들기」(`/app/r/<앱>/<모델>/new`)에서 품번·공정·LOT 같은 연결을 골라 등록합니다(선택지는 앞 500개). 이미 등록한 기록의 LOT·작업지시·공정을 바꿀 때는 관리 화면을 씁니다 — 보류 중 LOT의 실적·출하 차단, 양품+불량 ≤ 투입, 라우팅 순서는 새로 만들기에서도 그대로입니다.
- **PPAP**: 18개 요소 표(요구·문서·증적 기록·비고)가 보이고, 문서·기록이 이어진 요소는 「양식지」 열의 「문서」「기록」을 눌러 그 문서·기록을 양식지(A4 한 장)로 새 탭에서 엽니다. 요소 화면에서 요구·비고·문서·증적 기록을 고칩니다. 증적 기록은 그 제출 품목의 관리계획서·검사기준·검사·4M 변경(종류마다 최근 50건)에서 고르고, 요소의 「⋯」 메뉴에서도 양식지를 엽니다. 심사 항목의 증적 표도 같은 「양식지」 열이 있습니다. PSW 승인 뒤에는 요소가 잠겨 기록 화면에서 고칠 수 없습니다. 승인 뒤 제출일·고객 승인일은 관리 화면에서 넣습니다.

## 사내망 서비스 (팀 공유)

혼자 쓸 때는 위의 `runserver`로 충분합니다. 팀원이 각자 PC에서 접속하게 하려면 아래처럼 띄웁니다(waitress, 무료).

```powershell
powershell -ExecutionPolicy Bypass -File scripts\serve.ps1 -HostName QA-PC01 -ListenIp 192.168.0.10   # QA-PC01 = 이 PC 이름, 192.168.0.10 = 사내망 IP
```

- `-ListenIp`를 빼면 이 PC의 모든 네트워크 연결(외부 Wi-Fi·VPN 포함)에서 접속을 받습니다. 노트북에서 띄울 때는 꼭 사내망 IP를 지정합니다(`ipconfig`로 확인).

- 팀원은 `http://QA-PC01:8000`으로 접속합니다. Windows 방화벽이 묻으면 "개인/도메인 네트워크 허용"을 선택합니다.
- 서명·세션용 비밀키는 처음 실행할 때 `data/secret_key.txt`에 자동으로 만들어집니다(Git에 올라가지 않음). 이 파일을 지우면 모두 다시 로그인해야 합니다.
- 첨부파일(문서 원본)은 로그인한 사용자만 내려받을 수 있습니다.

## 휴대폰에서 사진 찍기

품질보증 및 개선 > "부적합 등록"(`/app/nc-new`)에서 휴대폰 카메라로 바로 찍어 올릴 수 있습니다. 먼저 **회사 보안 정책(사내망 포트 개방 가능 여부)을 확인**하세요.

1. `QMS_ALLOWED_HOSTS=<PC IP>` 환경변수를 설정합니다.
2. `python manage.py runserver 0.0.0.0:8000`으로 띄웁니다(또는 `scripts\serve.ps1`의 host를 바꿉니다).
3. 관리자 PowerShell에서 방화벽을 엽니다.
   `New-NetFirewallRule -DisplayName QMS -Direction Inbound -LocalPort 8000 -Protocol TCP -Action Allow`
4. 휴대폰(같은 사내망)에서 `http://<PC IP>:8000/app/nc-new`로 접속합니다.

## 새 기능 사용법

- **부적합 간편 등록 · 카메라**: `/app/nc-new`(LOT 이력의 「부적합 등록」 단추는 LOT 번호를 채워 연다)에서 LOT 번호(바코드 스캔 가능), 발생 유형, 내용, 부적합 수량, 사진만 적고 저장합니다. 휴대폰에서는 "사진"을 누르면 카메라가 열리고 여러 장을 올릴 수 있습니다(아이폰 HEIC 가능, 한 장 10MB까지). 저장하면 LOT과 하위 계보가 바로 보류됩니다. 나머지 항목(부적합 유형·공정·긴급 조치 등)은 부적합 화면에서 보완해야 처분할 수 있습니다. 저장 후 나오는 「부적합 상세 열기」·「LOT 이력 보기」로 이어 갑니다.
- **메일 보내기**: 승인(MRB 서명)된 부적합의 「⋯ → 메일 보내기」나 내 할 일 「메일 발송 대기」 줄(`/app/nc-mail/<번호>`, 옛 `/nc/<번호>/mail/`도 동작)에서 제목·본문을 복사해 **아마란스(웹메일)에 붙여넣고**, 사진은 "사진 ZIP"으로 받아 첨부합니다. 보낸 뒤 "보냈음 표시"를 누르면 발송 일시가 남습니다. 아래의 `QMS_SMTP_*` 환경변수를 설정했다면 수신자를 적고 바로 **SMTP로 발송**할 수도 있습니다(실패하면 보냈음 표시는 하지 않습니다).
- **삭제·수정 요청**: 일반 사용자는 기록 화면의 "삭제 요청"에 사유와 본인 비밀번호를 넣어 요청합니다. 요청은 내 할 일에 뜨고, 시스템 관리자는 그 줄을 눌러 「요청 처리」 화면(`/app/requests/<번호>`)에서 대상 기록 내용·먼저 지워야 할 기록을 보고 승인하거나 사유를 적어 거절합니다. 승인해야 삭제됩니다(부적합을 지우면 그 부적합이 만든 보류도 함께 사라지고, 같은 LOT에 걸린 다른 부적합의 보류는 그대로입니다). 검사기준서·관리계획서도 「⋯ → 수정 요청·삭제 요청」이 같은 화면 안 창으로 열립니다. 이미 승인된(잠긴) 기록은 "수정 요청" → 관리자 승인 후 **1회만** 수정할 수 있습니다(저장이 검증 오류로 실패하면 수정 권한은 남습니다). **시스템 관리자(슈퍼유저)는 요청 없이 바로 수정·삭제**하며, 모든 변경은 이력에 남습니다.
- **통합 검색**: 화면 위 검색창이나 `Ctrl+K`. LOT 번호를 정확히 넣고 Enter(바코드 스캐너 포함)하면 바로 그 LOT의 추적 화면으로 이동합니다. 품번·거래처(코드·이름)·부적합·8D·문서 등도 찾습니다(권한 있는 것만).
- **LOT 타임라인**: `/trace/`에서 LOT을 열면 공정·검사·부적합·출하·메모가 시간순으로 보입니다.
- **현장 메모**: `/memo/new/`에서 말한 사람(심사원·고객 등)과 내용, 사진을 적습니다. LOT·부적합 등에 연결하면 그 기록 이력에 보이고, 연결 안 한 메모는 미분류함(`/memo/inbox/`)에서 종류+번호로 연결합니다. 심사 날짜에 쓴 메모는 심사에 자동으로 묶입니다. 수정은 작성자만 할 수 있습니다.
- **심사 자료 출력**: `/app/audit-pack`(메뉴 심사 관리 → 「심사 자료 출력」 탭)에서 품번과 기간(기본 최근 90일)을 고르면 검사 요약·부적합·처분·CAPA·4M·관리계획서·메모를 한 장으로 모아(인쇄할 때는 머리줄·메뉴를 뺌) 인쇄/PDF로 저장하고, "ZIP"으로 사진·문서 원본을 한 번에 받습니다.
- **연차·급여**: `/app/me`는 **본인만** 볼 수 있습니다(시스템 관리자도 남의 것은 못 봄). 같은 DB에 저장되므로 서버 백업에 **포함**되고, 급여 명세서 파일은 `data\private\personal\`에 저장돼 백업에 함께 들어갑니다(웹 주소로는 열리지 않음). 아래 "개인 연차·급여 자료"를 참고하세요.
- **공장 종합현황**: `/overview/`(또는 내 할 일 오른쪽 위 "공장 종합현황")는 DB에 등록된 작업지시·실적·검사·부적합·CAPA·계측기 기록을 생산·품질 카드로 모아 보여줍니다. 설비 실시간 값은 없고, "계획"은 작업지시의 계획 수량입니다. 카드를 누르면 같은 조건으로 걸러진 목록이 열리며, 볼 권한이 없는 카드는 보이지 않습니다.
- **관련 기록**: LOT·작업지시·생산실적·부적합·보류·출하·검사·고객 클레임·SCAR 화면 아래 "관련 기록" 칸에서 이어진 기록(최대 5건)과 "추적성 조회(LOT 이력)" 버튼으로 바로 이동합니다. 6건 이상이면 "전체 N건 보기"로 걸러진 목록이 열립니다.
- **번호 자동 부여**: 품번은 새 화면 `/app/items`의 "새 품번"에서 "자동 번호" 스위치를 켜고 규칙(제품코드·원자재·도면 품번·표준품)을 고르면 칸마다 드롭다운이 나오고, 다음 번호를 미리 보여 줍니다. 저장할 때 서버가 번호를 다시 계산해 확정합니다. 미리보기 옆 "직접 고치기"를 누르면 그 번호를 품번 칸에 채워 직접 고칠 수 있습니다. 문서번호는 관리 화면(`/admin/`)의 문서 추가에서 문서번호를 비워 두고 "채번 규칙"을 고릅니다. 규칙을 고르면 `?rule=<id>`가 붙어 화면이 그 규칙의 드롭다운으로 다시 열리므로, 다른 칸을 적기 전에 **채번 규칙부터 고르세요.** 문서 개정의 `개정` 칸을 비우면 마지막 숫자 개정 + 1(첫 개정은 0)로 채웁니다. 긴 번호는 목록·상세에서 마우스를 올리면 자리별 뜻이 보입니다. 직접 입력은 그대로 허용되고 모양 검사는 하지 않습니다.
- **번호 체계 바꾸는 법**: 관리 화면의 "채번 코드값"·"채번 규칙"에서 고칩니다(품질엔지니어·품질팀장). 기존 번호는 다시 매기지 않고, 바꾼 규칙은 새 번호부터 적용됩니다. 저장된 규칙의 이름·대상·틀은 고칠 수 없으므로 새 틀은 규칙을 새로 추가하고 옛 규칙을 "사용 중지"합니다.

  | 바뀌는 것 | 하는 일 | 개발자 필요 |
  | --- | --- | --- |
  | 고객사·산업·자재 등 코드값 추가·이름 변경 | 관리 화면 "채번 코드값"에서 추가·수정 | 아니오 |
  | 코드값 폐지 | "사용 중지" (예전 번호 풀이는 유지) | 아니오 |
  | 회사 약칭(KEN → 다른 이름), 자릿수, 자리 순서, 도면코드 목록 | 새 틀로 규칙을 추가하고 옛 규칙을 사용 중지 | 아니오 |
  | 위 규칙을 참조하던 규칙(예: 양식 → 관리표준) | 새 규칙을 참조하는 규칙도 하나 더 추가 | 아니오 |
  | 새 번호 종류 | 규칙 추가 | 아니오 |
  | 새 코드 묶음(예: "공장") | `CodeValue.GROUPS`에 1줄 추가 + 마이그레이션 | 예 (작음) |

  예: 회사 약칭이 ABC로 바뀌면 `ABC-{관리표준 문서구분}{부서}-{일련2}` 규칙(이름 예: 관리표준2)을 추가하고 관리표준을 사용 중지합니다. ABC 문서의 양식 번호를 받으려면 `{문서:관리표준2}-{일련2}` 규칙도 추가합니다. KEN 번호의 풀이는 그대로 나옵니다.
- **기존 기록을 거래처·부서에 연결(`link_masters`)**: 거래처·부서·사용자를 등록한 뒤, 예전 기록의 글자 칸(LOT 공급자, 출하·클레임·PPAP·고객사별 8D 기한의 고객사, SCAR 공급자, 내부심사 피심사 부서·심사원)을 새 기준정보에 연결합니다. 글자 칸은 그대로 두고 비어 있는 연결 칸만 채웁니다. 공백·대소문자는 무시하고, 후보가 정확히 1개일 때만 연결합니다(거래처는 코드·이름·영문명, 공급자·고객사 구분이 맞아야 함).

  ```powershell
  .\.venv\Scripts\python manage.py link_masters                                              # 미리보기: 아무것도 바꾸지 않고 연결될 건수와 못 찾음·여러 후보·구분 불일치를 보여 줌
  .\.venv\Scripts\python manage.py link_masters --apply --backup-dir "\\NAS\quality\qms-backup" # 먼저 backup을 실행한 뒤 연결
  ```

  미리보기에서 못 찾은 이름은 거래처·부서를 등록하거나 이름을 맞춘 뒤 다시 실행합니다. `--backup-dir` 대신 환경변수 `QMS_BACKUP_DIR`을 써도 됩니다. 연결 기록은 변경 이력에 "기준정보 연결(link_masters)"로 남습니다.
- **예시 데이터(`demo_data`)**: 메뉴마다 사용성을 검토할 수 있게 하위 메뉴까지 예시 기록을 넣습니다. 번호·코드·이름은 모두 `EX-`로 시작하고, 여러 번 실행해도 같은 기록이 다시 생기지 않습니다. 기존 기록은 바꾸거나 지우지 않고 새 행만 더합니다. 서명용 예시 사용자 3명(ex_inspector·ex_lead·ex_engineer)은 로그인할 수 없는 비밀번호로 만듭니다. 연차·급여 예시는 첫 시스템 관리자에게 실제 기록이 없을 때만 넣습니다. 계산 화면(내 할 일·종합현황·KPI 등)·엑셀 양식·보안 설정 화면은 건너뛰고, 이유를 출력합니다. 운영 DB에 넣기 전에는 `backup`을 먼저 실행하세요(지울 때는 `EX-` 기록을 직접 지우거나 백업으로 복원).

  ```powershell
  .\.venv\Scripts\python manage.py backup "\\NAS\quality\qms-backup"
  .\.venv\Scripts\python manage.py demo_data
  ```

## 모듈

- **MES**: 품번·BOM·공정 라우팅, 작업지시·생산실적(투입·양품·불량, 이전 공정 실적 없으면 등록 차단, 진도율), LOT·계보(분할·병합), 출하
- **CAPA**: 8D·SCAR·부적합·심사 발견사항 화면의 "CAPA 만들기" → 담당·기한 → 조치 완료 → 유효성 확인("유효")해야 종결
- **반복 부적합 → CAPA 제안**: 같은 품번·같은 부적합 유형이 최근 90일 동안 CAPA 없이 3건 나오면 내 할 일 「반복 부적합」과 아침 알림에 뜨고, 그 부적합 화면 위에 노란 안내와 「CAPA 만들기」 버튼이 나옵니다. 누르면 가장 최근 부적합을 출처로, 제목이 「반복 부적합: 품번 유형 (최근 90일 N건)」으로 채워진 CAPA 새로 만들기 화면이 열립니다. CAPA를 만든 부적합까지는 그 CAPA가 다루므로, 그 뒤로 다시 3건이 쌓여야 또 제안합니다. 유형은 앞뒤 공백만 무시하고 글자가 같아야 같은 유형이며, 유형이 빈 부적합은 세지 않습니다. CAPA 모듈이 꺼져 있으면 제안하지 않습니다.
- **심사**: 내부(1자)·고객(2자)·인증(3자) 심사 계획·실시·발견사항(중부적합/경부적합/관찰/개선기회). 중·경부적합은 CAPA가 연결돼야 심사 종결
- **PPAP**: 제출을 만들면 AIAG 18요소가 수준(1~5)에 맞게 생성되고 관리계획서·출하검사가 자동 연결. 제출(S) 요소에 문서·기록이 모두 있어야 PSW 승인 서명 가능, "인쇄/PDF"가 PSW 요소표
- **부적합**: 등록 즉시 LOT과 하위 계보 전체 자동 보류 → 투입·출하 차단. MRB 처분(재작업·수리는 재검사 합격 기록 필요, 특채는 고객 승인번호 필요, 폐기·반품은 보류 유지)
- **검사**: 검사기준(개정·승인 서명, 승인 후 잠금) → 검사 → "저장하고 판정하기" → 불합격이면 부적합 자동 등록
- **고객 클레임(8D)**: 접수 즉시 부적합·보류, 고객사별 D3(봉쇄, 시간)·D4(원인)·D5(대책)·D8(종결, 일) 기한, D1~D8 모두 채워야 종결. D1~D3은 D3 기한, D4는 D4, D5는 D5, D6~D8은 D8 기한을 따르고, 지금 단계가 기한을 넘기면 클레임 목록 「지연」 칸에 「D4 근본 원인 3일 지연」처럼 뜹니다. 내 할 일·아침 알림도 지금 단계의 기한으로 셉니다. 기본값은 24시간·5일·10일·60일이며 기한은 D3 ≤ D4 ≤ D5 ≤ D8 순서여야 저장됩니다.
- **SCAR**: 공급자 시정조치 요구, 회신 기한
- **문서**: 원본 파일 + 개정 + 승인 서명, 최신 승인본 = 승인된 최신 개정
- **심사 증적**: 체크리스트 항목에 문서·기록 연결, 미비 항목 표시
- **보고서**: 각 기록 화면의 「양식지 · 인쇄」 → A4 한 장 양식지(`/app/r/<앱>/<모델>/<번호>/print`, 머리말·작성/승인 결재란·구역 표)에서 인쇄/PDF 또는 `.xlsx` 받기, 또는 등록한 고객 엑셀 양식(셀 매핑)으로 다운로드. 부적합은 ①~⑦ 구역과 사진, CAPA·8D·SCAR·4M 변경·내부심사는 보고서 구역 표, 그 밖의 기록은 항목 표로 나옵니다. 승인 전 기록에는 `초안 — 승인 전` 표시가 들어갑니다. 옛 인쇄 주소(`/print/...`)는 새 양식지로 넘어갑니다
- **출하 기록·출하성적서(COA)**: 출하 기록 화면 위에 「출하 여정」(LOT 생성 → 작업 시작 → 작업 완료 → 공정검사 → 출하검사 → 출하, 단계마다 일시, 빠진 단계는 「없음」·출하검사 없음/불합격은 빨간 칸, 보류 중이면 「보류」 태그)과 「검사 근거」(검사마다 특성·규격·측정 수·최소·최대·판정), 「투입 LOT · 수입검사」, 「부적합 · 변경점」(LOT·투입 LOT 부적합, 출하 전 승인된 4M 변경과 초품), 접힌 「LOT 전체 이력」이 나옵니다. 출하 목록에는 「출하검사」 판정 열이 있습니다. 머리의 「출하성적서」 버튼이 성적서가 됩니다(최신 합격 출하검사, 없으면 공정검사; 머리에 고객사·품목·LOT·수량·출하 일시·검사 근거, 끝에 투입 LOT 표). 고객 엑셀 양식은 대상 기록을 "출하"로 하고 매핑에 `{"A10": "coa_rows"}`처럼 표 시작 셀을 적으면 항목·특별특성·LSL·USL·단위·측정값·판정이 아래로 채워집니다
- **재발 방지**: 부적합·클레임 화면에 같은 품번(계보 포함)·같은 부적합 유형·비슷한 설명의 과거 종결 사례와 그 8D의 D4·D7을 표시
- **검사 입력 화면**: LOT 바코드를 스캔하면 승인된 현재 검사기준이 뜨고, 값을 넣는 즉시 규격 이탈을 빨간색으로 표시. "판정"은 전부 저장되거나(자격·교정·기준 검사 통과) 아무것도 저장되지 않습니다
- **입고 등록·바로가기**: 없는 LOT 번호를 넣으면 그 자리에서 입고 등록(품목은 승인된 검사기준이 있는 것만, 공급자는 기존 입력값 목록)을 하고 바로 검사합니다. LOT 화면에서 기준서·이 품목 지난 성적서·수입검사 관리대장·부적합 관리대장으로 이동하고, 결과 화면에서 성적서를 인쇄합니다. 불합격이면 측정 화면에서 고른 부적합 유형·불량수량이 자동 등록된 부적합에 들어갑니다. 관리 화면의 "검사 추가"는 이 화면으로 이동합니다(지난 검사 소급 입력은 `/admin/qms/inspection/add/?full=1`)
- **공급자 등급**: 공급자 평가(`/app/suppliers`)에 거래처 등급과 성적으로 낸 제안 등급이 나오고, 거래처를 고칠 권한이 있으면 「등급 반영」으로 거래처 등급·평가일을 바꿉니다(이력 남음). 등급 C·D나 조건부 승인·거래 중지 공급자의 LOT은 수입검사 화면과 LOT 화면에 강화 검사 안내가 뜹니다(경고만, 검사를 막지 않음)
- **KPI 입력**: 부적합에 부적합 유형·부적합 수량·실패비용, 클레임에 불량 수량, 구매 자재 LOT에 공급자를 적어야 KPI와 공급자 성적표가 채워집니다
- **SPC**: 부분군 n=1이면 I-MR, 2~10이면 X̄-R 관리도, Cpk, 경보(관리한계 이탈, R/MR 이탈, 연속 9점). 특별특성(CC·SC)은 경보 시 부적합 자동 등록·보류, 일반 항목은 내 할 일에 경보 표시
- **계측기**: 교정 대장. 측정값에 계측기를 적으면 교정 기한이 지난 계측기는 거부. 교정 14일 전부터 내 할 일에 표시. 목록의 "남은 일수" 열에 `D-n`·`오늘까지`·`기한 지남 n일`이 보입니다. 계측기마다 종류·제조사·모델·시리얼 번호·측정 범위·분해능·관리 부서·보관 위치·담당자·교정 구분(사외/사내)·교정 기관을 적고, 기록 화면 아래 "교정 이력" 표의 「추가」로 교정일·기관·결과·성적서 번호·비고를 남깁니다. 합격 이력은 최근 교정일을 앞당기고, 불합격 이력은 계측기를 사용 중지합니다(측정 거부)
- **설비 예방보전**: 메뉴 "생산관리 (MES)"의 "설비·예방보전"에 설비·금형·지그·공구·유틸리티를 코드·이름·종류·공정·위치·제조사·모델·시리얼·담당자·상태(가동·정지·수리 중·폐기)로 등록하고, 예방보전 주기(일)와 최근 예방보전일을 적으면 다음 예방보전일이 계산됩니다(주기를 적으면 최근 예방보전일도 적어야 합니다). 설비 기록 화면 아래 "보전 이력" 표의 「추가」로 구분(예방·사후·예지·개선)·실시일·내용·교체 부품·정지 시간(분)·비용을 남깁니다. 예방 이력은 최근 예방보전일을 그 실시일로 앞당기고(더 옛날 날짜면 그대로), 실시일은 오늘 이후일 수 없으며, 구분·실시일은 등록 후 고치지 않습니다. 다음 예방보전일이 지났거나 7일 안에 오는 설비(폐기 제외)는 내 할 일·알림 메일 「설비 예방보전」과 설비 목록 「지연」 탭(지난 것만)에 뜹니다. 기한이 지나도 생산을 막지는 않습니다.
- **측정시스템 분석(MSA)**: 계측기 기록 화면 아래 "측정시스템 분석(MSA)" 표, 또는 메뉴 "측정시스템 분석(MSA)"(계측기 관리 탭)에서 등록합니다. 종류는 GR&R·편의·선형성·안정성·계수형입니다. GR&R은 원자료 파일(CSV·엑셀, 첫 줄 열 제목 `부품·측정자·반복·측정값`, 한 줄에 측정 1회, 부품 2~10개·측정자 2~3명·반복 2~3회)을 올리면 평균·범위법(AIAG)으로 EV·AV·GRR·PV·TV·%GRR·구별 범주(ndc)를 계산하고 판정합니다(%GRR 10 이하 적합, 30 이하 조건부, 30 초과 또는 ndc 5 미만 부적합). 파일 없이 %GRR·ndc를 직접 적어도 판정은 숫자로 정해집니다. 특성에 규격 상·하한이 있으면 공차 대비 %GRR도 요약에 남습니다. 그 밖의 종류는 판정을 직접 고릅니다. 등록 후에는 비고만 고칩니다. 계측기의 최근 분석이 부적합이면 계측기 기록 화면 위에 개선·재분석 안내가 뜹니다(측정은 막지 않음).
- **검사원 자격**: 검사구분별 자격·유효기한. 그 검사구분에 자격 기록이 하나라도 생기면 그때부터 자격자만 판정 가능 (자동수집 `collect`은 검사자가 없어 판정되지 않으므로, 자격을 쓰는 검사구분은 자동수집 대신 직접 입력). 유효기한이 30일 안에 끝나거나 지난 자격은 내 할 일·알림 메일의 「검사원 자격 만료」에 뜨고(같은 검사원·구분에 더 늦게 끝나는 새 자격을 넣으면 빠짐), 목록의 「만료 임박」 탭에서도 볼 수 있습니다. 갱신 자격은 화면이나 엑셀 일괄 등록으로 넣습니다.
- **관리계획서**: 공정·특성·특별특성·규격·S/O/D·조치우선순위(AP)·PFMEA 칸(영향·원인·예방 관리·권고 조치). 승인 후 "검사기준 초안 만들기"로 검사기준 생성, PFMEA 양식 출력·정합성 경고
- **경영검토**: 메뉴 「분석 및 보고서 → 경영검토」에서 검토일·검토 기간·의장·참석자를 넣고 등록하면, 그 기간의 품질 성과(검사 판정·합격률, 부적합 발생·미종결, 켜진 모듈의 클레임·CAPA·심사, 등급 C·D 공급자, 교정 기한 지난 계측기)와 직전 경영검토 조치의 완료·미완료가 자동으로 채워집니다(이미 적은 칸은 그대로). 내·외부 이슈·고객 피드백·자원·리스크·개선 기회(ISO 9001 9.3.2)를 적고, 검토 결과를 적어야 품질팀장 승인 서명을 할 수 있습니다. 승인 후에는 회의록이 잠기고, 아래 「조치 사항」 표(할 일·담당자·기한·완료일)는 계속 기록합니다. 「양식지 · 인쇄」가 경영검토 회의록입니다
- **4M 변경**: 고객 통보 대상은 고객 승인번호가 있어야 승인. 진행 단계 보류·반려 또는 고객 반려면 승인 거부, 「승인 완료」 단계는 승인 서명으로만. 승인 후 적용 일시부터 그 품번의 합격 검사(초품)가 나올 때까지 출하 차단

### 모듈 설정

쓰지 않는 모듈은 시스템 관리자가 메뉴 「모듈 설정」(`/app/modules`, 서버도 시스템 관리자만 허용)에서 스위치로 끕니다. 규칙에 걸리면 끄지 않고 이유를 보여 줍니다. 기록이 없으면 켜져 있는 것입니다.

- 끌 수 있는 모듈: 생산관리(작업지시·실적·출하·설비), 검사, 4M 변경, CAPA, 고객 클레임, 공급자(SCAR), PPAP, 심사, 문서 관리, 품질 KPI. 홈·LOT·부적합·보류·기준정보·시스템·개인은 끌 수 없습니다.
- 4M 변경은 검사가, 내부심사는 CAPA가 켜져 있어야 켤 수 있습니다. 거꾸로 이 모듈이 켜져 있으면 검사·CAPA를 끌 수 없습니다.
- 꺼진 모듈의 메뉴는 사라지고, 화면·API는 일반 사용자에게 404입니다. 시스템 관리자는 조회만 할 수 있고 저장은 403입니다. 새 화면(`/app/`)에서는 「비활성 모듈」 안내가 나옵니다.
- 열린 기록(완료 안 된 작업지시, 미판정 검사, 초품 합격 전 4M, 미종결 CAPA·클레임·SCAR·내부심사, 미승인 PPAP)이 있으면 끌 수 없고 번호 목록이 나옵니다.
- 꺼진 뒤에도 시스템 관리자는 CAPA·클레임·SCAR·내부심사를 관리 화면에서 종결하고, 검사 입력으로 판정(4M 초품·재검사)할 수 있습니다.
- 꺼진 모듈의 기록은 내 할 일·기한·알림 메일·위젯·종합현황에서 빠집니다. LOT 이력·검색·관련 기록에는 「비활성 모듈 기록 N건」으로만 나옵니다.
- 꺼진 모듈을 대상으로 한 엑셀 보고서는 404, 엑셀 일괄 등록은 거부됩니다. 검사 모듈이 꺼지면 `collect`는 수집하지 않고 파일을 수신함에 둡니다. 심사 자료 출력(`/app/audit-pack`)에서는 꺼진 모듈 구역이 빠집니다.
- 고객사별 8D 기한은 「고객 및 공급자 › 고객사별 8D 기한」에 있고 고객 클레임 모듈에 속합니다.
- 모듈을 꺼도 업무 규칙(LOT 보류 인터록 등)과 기존 기록은 그대로입니다.

## 사용자와 역할

메뉴 "기준정보 및 시스템 관리" → **사용자·조직도**(`/app/users`, 시스템 관리자만)에서 관리합니다.

- 왼쪽 조직도에 부서와 인원이 트리로 보입니다. 인원이나 부서를 끌어 다른 부서 위에 놓으면 옮겨집니다(부서를 자기 하위로 옮기면 거부). 부서가 없는 인원은 "부서 없음" 아래에 있습니다.
- 인원을 누르면 오른쪽에 인사 정보(성·이름·부서·사번·직위·직책·연락처), 계정(아이디·메일·계정 사용·시스템 관리자), 역할(아래 그룹)과 계정 변경 기록이 나옵니다.
- 「사용자 추가」로 계정을 만듭니다(로그인 권한은 자동). 새 사용자, 역할·관리자 권한 변경, 「비밀번호 초기화」는 **관리자 비밀번호를 다시 입력**해야 저장됩니다. 비밀번호는 서버의 비밀번호 규칙(길이 등)을 통과해야 합니다.
- 사용자는 지우지 않고 "계정 사용"을 끕니다(작성자·승인자 이력 보존). 자기 계정은 끄거나 관리자 권한을 뗄 수 없습니다.
- 부서는 「부서 추가」·「부서 수정」으로 기록 화면에서 고칩니다.

| 그룹 | 권한 |
| --- | --- |
| 품질엔지니어 | 모든 기록 작성·수정 (삭제 불가) |
| 품질팀장 | 품질엔지니어 권한 + 승인 서명, MRB 처분 |
| 검사원 | LOT·계보·출하 등록, 검사·측정값 입력 (품질 KPI·공급자 성적표·SPC 관리도·엑셀 일괄 등록은 볼 수 없음) |

KPI(화면과 내 할 일 위젯)는 소속 부서 것만 보입니다. 지금은 위 세 그룹이 모두 품질 부서입니다. 품질팀장은 모든 부서의 KPI를 봅니다.

## 회사 데이터와 백업

회사 데이터(DB, 첨부파일, 들여오기 원본)는 `data/` 폴더에만 저장되며 Git에 올라가지 않습니다. 위치를 바꾸려면 환경변수 `QMS_DATA_DIR`을 지정합니다. 엑셀 일괄 등록으로 확정한 원본 파일은 `data/imports/`에 쌓이고, 환경변수 `QMS_IMPORT_DIR`로 따로 옮길 수 있습니다(예: NAS). `backup`은 이 폴더도 함께 복사합니다.

```powershell
# 수동 백업
.\.venv\Scripts\python manage.py backup "\\NAS\quality\qms-backup"
# 매일 18:00 자동 백업 등록 (Windows 작업 스케줄러)
powershell -ExecutionPolicy Bypass -File scripts\register_backup_task.ps1 -Dest "\\NAS\quality\qms-backup"
```

30일이 지난 백업은 자동으로 지워집니다. 백업에는 DB와 `media/` 외에 `private/`(급여 명세서)와 `attachments/`(기록에 붙인 첨부파일)도 들어갑니다.

백업에는 모든 사람의 연차·급여 기록과 명세서 파일이 들어 있습니다. 자동 백업 등록 스크립트는 백업 폴더를 등록한 계정(과 관리자)만 열 수 있게 잠급니다. 잠그지 못했다는 경고가 나오면(NAS 권한 등) IT팀에 그 폴더를 이 계정 전용으로 설정해 달라고 요청합니다. 수동 백업 폴더도 팀 공유 폴더에 두지 않습니다.

복구는 먼저 리허설로 백업이 쓸 만한지 확인한 뒤 실행합니다. 분기마다 리허설을 한 번 해 두면 "백업은 있는데 복구가 안 되는" 일을 막을 수 있습니다.

```powershell
.\.venv\Scripts\python manage.py restore "\\NAS\quality\qms-backup\qms-20261026-180000"           # 리허설: 무결성 검사 + 건수 확인
.\.venv\Scripts\python manage.py restore "\\NAS\quality\qms-backup\qms-20261026-180000" --apply   # 실제 복원 (서버를 먼저 끄세요)
```

실제 복원 전의 데이터는 `data/pre-restore-날짜/`에 따로 보관됩니다. PostgreSQL을 쓸 때의 백업·복원 방식은 아래 "PostgreSQL" 절을 봅니다.

## PostgreSQL

환경변수 `QMS_DB_NAME`이 있으면 SQLite 대신 PostgreSQL을 씁니다. 없으면 `data/db.sqlite3`를 씁니다.

| 사용자 환경변수 | 값 | 설명 |
| --- | --- | --- |
| `QMS_DB_NAME` | `qms` | DB 이름. 지우면 SQLite로 돌아갑니다 |
| `QMS_DB_USER` | `qms` | 접속 계정 |
| `QMS_DB_PASSWORD` | | 접속 비밀번호 |
| `QMS_DB_HOST` / `QMS_DB_PORT` | `localhost` / `5432` | 기본값이면 지정하지 않습니다 |
| `QMS_PG_BIN` | `C:\Program Files\PostgreSQL\18\bin` | `pg_dump`·`pg_restore` 폴더. 이 기본 위치면 지정하지 않습니다 |

- PostgreSQL 18은 이 PC에서만 접속하도록(`localhost`) 설치합니다. 접속 드라이버는 `requirements.txt`의 `psycopg[binary]`입니다.
- 백업은 `pg_dump`로 `db.dump` 파일을 만들고, 복원 리허설은 임시 DB(`qms_restore_check`)에 실제로 풀어 건수를 센 뒤 지웁니다. `--apply`는 현재 DB를 `data/pre-restore-날짜/db.dump`로 보관한 뒤 `pg_restore`로 한 번에 복원합니다(중간에 실패하면 현재 DB가 그대로 남음).
- SQLite에서 옮길 때: `PYTHONUTF8=1`을 켠 상태에서 `python manage.py dumpdata --natural-foreign -e contenttypes -e auth.permission -o all.json`로 내보내고, 빈 PostgreSQL DB에 `migrate` → 마이그레이션이 넣은 기본 행 비우기 → `loaddata all.json` → `migrate` 순으로 싣습니다. `PYTHONUTF8=1`이 없으면 파일이 cp949로 저장돼 `loaddata`가 실패합니다. 이미 지운 모델의 권한 참조는 빼고 싣습니다.
- SQLite로 되돌리려면 `QMS_DB_NAME`을 지우고 서버를 다시 켭니다. 전환 뒤 PostgreSQL에 입력한 데이터는 SQLite에 없습니다.
